## 1. 시스템 개요

### 1.1 목적

**민사소송법 서술형 답안 자동 첨삭 시스템**

사용자가 제출한 민사소송법 서술형 답안을:
- 📊 **쟁점 분석**: 모범 답안과 비교하여 쟁점 포함 여부 확인
- 🧠 **논리 평가**: 논리 일관성 및 논증 강도 평가
- ✍️ **표현 검토**: 명료성, 격식성, 문법 검토
- 📝 **피드백 생성**: 사용자 친화적인 구조화된 피드백 제공

### 1.2 핵심 기술 스택

```
Backend:  FastAPI + SQLAlchemy (Async) + PostgreSQL (NeonDB)
ML:       EXAONE (LG AI Research) - Fine-tuned for Legal Domain
Architecture: Domain-Driven Design (DDD) + MCP (Model Context Protocol)
```

### 1.3 시스템 특징

- **Modular Monolith**: 4개 독립 도메인으로 구성된 모듈식 모놀리스
- **MCP 통신**: 도메인 간 표준화된 비동기 메시지 기반 통신
- **Weakened Star Topology**: Core에 직접 의존하지만 도메인 간은 MCP로 통신
- **비동기 처리**: 모든 DB 및 ML 연산은 AsyncIO 기반

## 3. 도메인별 상세 구조

### 3.1 Reference Domain (기준 지식)

**역할**: 문제, 모범 답안, 쟁점 구조 관리

```
app/domain/reference/
├── models.py           # SQLAlchemy ORM 모델
│   ├── Problem         # 문제 (title, content, meta)
│   ├── ReferenceAnswer # 모범 답안 (problem_id, content, structure)
│   └── Issue           # 쟁점 (reference_answer_id, type, title, keywords)
├── schemas.py          # Pydantic 요청/응답 모델
├── repositories.py     # DB CRUD 레이어
├── services.py         # 비즈니스 로직
└── __init__.py         # 모듈 export
```

**DB 테이블**:
```
problems (id, title, content, meta, created_at, updated_at)
    └─> reference_answers (id, problem_id, content, structure, ...)
            └─> issues (id, reference_answer_id, issue_type, title, ...)
```

**API 엔드포인트** (16개):
- Problems: CRUD (5개)
- Reference Answers: CRUD + by_problem (5개)
- Issues: CRUD + by_reference + extract (6개)

---

### 3.2 Submission Domain (제출 답안)

**역할**: 사용자 답안 제출 및 구조 분석

```
app/domain/submission/
├── models.py
│   ├── UserAnswer      # 사용자 답안 (problem_id, type, content, status)
│   └── AnswerStructure # 구조 분석 (paragraphs, sentences, statistics)
├── schemas.py
├── repositories.py
├── services.py
│   ├── UserAnswerService      # 답안 관리
│   ├── AnswerStructureService # 구조 분석 (문단/문장 분리)
│   └── OCRService             # 이미지 OCR (Phase 4에서 연동)
└── __init__.py
```

**DB 테이블**:
```
user_answers (id, problem_id, submission_type, status, raw_content, processed_content, ...)
    └─> answer_structures (id, user_answer_id, paragraphs, sentences, word_count, ...)
```

**API 엔드포인트** (10개):
- User Answers: CRUD + by_problem (7개)
- Structure Analysis: analyze + get (2개)
- OCR: process (1개)

---

### 3.3 Reasoning Domain (추론 엔진)

**역할**: EXAONE 기반 답안 분석

```
app/domain/reasoning/
├── models.py
│   ├── ReasoningTask   # 추론 작업 (task_type, status, config)
│   └── ReasoningResult # 추론 결과 (result_type, content, confidence)
├── schemas.py
│   ├── IssueAnalysisResult       # 쟁점 분석 결과
│   ├── LogicEvaluationResult     # 논리 평가 결과
│   └── ExpressionReviewResult    # 표현 검토 결과
├── repositories.py
├── services.py
│   ├── ReasoningTaskService      # 작업 관리
│   └── ReasoningEngine           # ⭐ 핵심 추론 엔진
│       ├── analyze_issues()          # 쟁점 분석
│       ├── evaluate_logic()          # 논리 평가
│       ├── review_expression()       # 표현 검토
│       └── comprehensive_analysis()  # 종합 분석
└── __init__.py
```

**DB 테이블**:
```
reasoning_tasks (id, task_type, status, user_answer_id, reference_answer_id, ...)
    └─> reasoning_results (id, task_id, result_type, content, confidence, ...)
```

**API 엔드포인트** (10개):
- Tasks: CRUD + by_answer (6개)
- Analysis: issues, logic, expression, comprehensive (4개)

**현재 상태**: 더미 분석 결과 반환 (Phase 5에서 EXAONE 실제 연동)

### 3.4 Feedback Domain (피드백 생성)

**역할**: Reasoning 결과를 사용자 친화적 피드백으로 변환

```
app/domain/feedback/
├── models.py
│   ├── Feedback        # 종합 피드백 (overall_score, scores, summary, strengths, weaknesses)
│   └── FeedbackItem    # 개별 항목 (item_type, severity, title, description, suggestion)
├── schemas.py
├── repositories.py
├── services.py
│   ├── FeedbackService       # 피드백 관리
│   └── FeedbackGenerator     # ⭐ 피드백 생성 엔진
│       ├── generate_from_reasoning()       # Reasoning → Feedback 변환
│       ├── _generate_issue_feedback()      # 쟁점 피드백
│       ├── _generate_logic_feedback()      # 논리 피드백
│       ├── _generate_expression_feedback() # 표현 피드백
│       ├── _generate_comprehensive_feedback() # 종합 피드백
│       └── generate_report()               # 전체 리포트
└── __init__.py
```

**DB 테이블**:
```
feedbacks (id, user_answer_id, reasoning_task_id, feedback_type, overall_score, scores, ...)
    └─> feedback_items (id, feedback_id, item_type, severity, title, description, suggestion, ...)
```

**API 엔드포인트** (8개):
- Feedbacks: CRUD + by_answer (6개)
- Generation: generate, report (2개)

```
┌──────────────────────────────────────────────────────────────────┐
│                        사용자 답안 제출 플로우                      │
└──────────────────────────────────────────────────────────────────┘

[1] 사용자가 답안 제출
    │
    ├─ 텍스트 직접 입력

    │  {
    │    "problem_id": "uuid",

    │  }

         "problem_id": "uuid",

       }
       │
       └─> [OCR 처리]
           POST /api/v1/submission/answers/{id}/ocr
           → processed_content 생성

    ▼

[2] 답안 구조 분석
    POST /api/v1/submission/answers/{id}/analyze
    │
    ├─ 문단 분리 (빈 줄 기준)
    ├─ 문장 분리 (., ?, ! 기준)
    └─ 통계 생성 (문단 수, 문장 수, 단어 수)
    │
    └─> AnswerStructure 생성
        {
          "paragraphs": [...],
          "sentences": [...],
          "word_count": {"total": 250}
        }

    ▼

[3] 추론 작업 시작 (Reasoning Engine)
    POST /api/v1/reasoning/analyze/{type}
    │
    ├─ [쟁점 분석]
    │  POST /api/v1/reasoning/analyze/issues
    │  {
    │    "user_answer_id": "uuid",
    │    "reference_answer_id": "uuid",
    │    "problem_id": "uuid"
    │  }
    │  │
    │  └─> EXAONE 모델 실행 (현재: 더미)
    │      - 모범 답안의 쟁점 추출
    │      - 사용자 답안과 비교
    │      - 포함률 계산
    │      │
    │      └─> ReasoningResult (issue_analysis)
    │          {
    │            "identified_issues": ["쟁점1", "쟁점2"],
    │            "missing_issues": ["쟁점3"],
    │            "coverage_rate": 0.67
    │          }
    │
    ├─ [논리 평가]
    │  POST /api/v1/reasoning/analyze/logic
    │  │
    │  └─> EXAONE 모델 실행
    │      - 논리 일관성 분석
    │      - 논증 강도 측정
    │      - 약점 식별
    │      │
    │      └─> ReasoningResult (logic_evaluation)
    │          {
    │            "coherence_score": 0.78,
    │            "argument_strength": 0.72,
    │            "weak_points": ["논리 비약", "근거 부족"]
    │          }
    │
    ├─ [표현 검토]
    │  POST /api/v1/reasoning/analyze/expression
    │  │
    │  └─> EXAONE 모델 실행
    │      - 명료성 평가
    │      - 격식성 검사
    │      - 문법 검토
    │      │
    │      └─> ReasoningResult (expression_review)
    │          {
    │            "clarity_score": 0.75,
    │            "formality_score": 0.88,
    │            "issues": [{"type": "구어체", "content": "그런데"}]
    │          }
    │
    └─ [종합 분석] ⭐
       POST /api/v1/reasoning/analyze/comprehensive
       │
       └─> 위 3가지 분석 통합 실행
           └─> ReasoningTask (comprehensive)
               └─> 3개의 ReasoningResult 생성

    ▼

[4] 피드백 생성 (Feedback Generator)
    POST /api/v1/feedback/generate
    {
      "user_answer_id": "uuid",
      "reasoning_task_id": "uuid",
      "feedback_type": "comprehensive",
      "include_suggestions": true
    }
    │
    └─> ReasoningResult 조회 및 변환
        │
        ├─ 쟁점 피드백
        │  - 식별된 쟁점 → FeedbackItem (INFO, ✓ 제목)
        │  - 누락된 쟁점 → FeedbackItem (CRITICAL, ✗ 제목)

        │
        ├─ 논리 피드백
        │  - 약점 → FeedbackItem (WARNING)
        │  - 개선 제안 → suggestion 필드
        │
        ├─ 표현 피드백
        │  - 표현 문제 → FeedbackItem (SUGGESTION)
        │  - 개선안 제시 (original → suggestion)
        │
        └─> Feedback 생성
            {
              "overall_score": 75.5,
              "scores": {"issue": 67, "logic": 75, "expression": 82},
              "summary": "종합 점수 75.5점...",
              "items": [...]  // FeedbackItem 배열
            }

    ▼

[5] 최종 리포트 생성
    POST /api/v1/feedback/report
    {
      "user_answer_id": "uuid",
      "include_comprehensive": true
    }
    │
    └─> 해당 답안의 모든 Feedback 통합
        └─> FeedbackReport
            {
              "feedbacks": [...],  // 모든 피드백
              "report_summary": {
                "average_score": 75.5,
                "total_feedbacks": 4
              }
            }

    ▼

[6] 사용자에게 결과 제공 ✅
```
