## 1. 시스템 개요

### 1.1 목적

**변리사 민사소송법 서술형 답안지 자동 첨삭 시스템**

사용자가 제출한 민사소송법 서술형 답안을:
- 📊 **쟁점 분석**: 모범 답안과 비교하여 쟁점 포함 여부 확인
- 🧠 **논리 평가**: 논리 일관성 및 논증 강도 평가
- ✍️ **표현 검토**: 명료성, 격식성, 문법 검토
- 📝 **피드백 생성**: 사용자 친화적인 구조화된 피드백 제공

### 1.2 핵심 원칙

**"학습용 데이터셋(PDF)과 사용자 답안지(PDF)만 입력하면, 나머지는 전부 자동화"**

```
┌─────────────────────────────────────────────────────────────┐
│                    사용자 입력 영역                          │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  [1] 학습용 데이터셋 (PDF)                                   │
│      └── 문제, 모범답안, 사용자답안 포함                    │
│                                                              │
│  [2] 사용자 답안지 (PDF)                                     │
│      └── 첨삭할 답안지                                       │
│                                                              │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   자동화 영역 (전부 자동)                     │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  ✅ PDF 파싱/OCR                                            │
│  ✅ 학습 데이터 추출 및 NeonDB 저장                         │
│  ✅ 자동 학습 트리거 (데이터 10개 이상)                      │
│  ✅ 모델 자동 학습 (LoRA)                                    │
│  ✅ 진행률 실시간 모니터링                                   │
│  ✅ 모델 자동 배포 (ModelLoader 리로드)                      │
│  ✅ 답안 분석 (쟁점/논리/표현)                               │
│  ✅ 피드백 생성 및 저장                                     │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## 3. 데이터 입력 방법

### 3.1 학습용 데이터셋 입력 (PDF)

**목적**: 모델 학습을 위한 문제, 모범답안, 사용자답안 데이터

#### 방법 1: PDF 파일 직접 업로드 (현재 미구현, 향후 구현 예정)

**⚠️ 현재 상태**: PDF 파싱 기능은 아직 구현되지 않았습니다.
**현재 사용 가능**: 방법 2 (수동 데이터 입력)

```
[향후 구현 예정]
[1] PDF 파일 준비
    - 문제, 모범답안, 사용자답안이 포함된 PDF
    - 예: "민사소송법_문제집.pdf"

[2] API로 업로드
    POST /api/v1/training/data
    Content-Type: multipart/form-data
    {
      "file": "민사소송법_문제집.pdf",
      "problem_id": "uuid",  # 옵션 (이미 Reference에 있는 경우)
      "reference_answer_id": "uuid",  # 옵션
      "labels": {
        "issue_coverage": 0.75,
        "logic_score": 0.8
      }
    }

[3] 자동 처리 (구현 예정)
    - PDF 파싱 (PyPDF2 또는 OCR)
    - 문제/모범답안/사용자답안 추출
    - TrainingData 생성 (status=PENDING)
    - NeonDB 저장
```

**구현 위치** (향후):
- `app/domain/training/services.py` - PDF 파싱 로직 추가
- 또는 `training/shared/parse_legal_documents.py` 활용

#### 방법 2: 수동 데이터 입력

```
POST /api/v1/training/data
{
  "problem_text": "갑은 을에게 금전을 대여...",
  "reference_answer_text": "이 사건에서 문제되는 법률관계는...",
  "user_answer_text": "갑은 을에게 대여금을 청구할 수 있다...",
  "labels": {
    "issue_coverage": 0.75,
    "logic_score": 0.8
  },
  "problem_id": "uuid",  # 옵션
  "reference_answer_id": "uuid",  # 옵션
  "user_answer_id": "uuid"  # 옵션
}
```

**저장 위치**: `NeonDB.training_data` 테이블

### 3.2 사용자 답안지 입력 (PDF)

**목적**: 첨삭할 사용자의 답안지

#### 방법 1: 이미지 파일 업로드 (현재 구현됨)

```
[1] 이미지 파일 업로드
    POST /api/v1/submission/answers/image
    Content-Type: multipart/form-data
    {
      "problem_id": "uuid",  # 어떤 문제에 대한 답안인지
      "file": "사용자_답안지.jpg"  # 또는 PNG
    }

[2] UserAnswer 생성
    - submission_type = IMAGE
    - status = PENDING
    - raw_content = 이미지 경로
    - NeonDB 저장
```

#### 방법 2: OCR 처리 (현재 더미 구현, 실제 OCR 엔진 연동 예정)

```
[1] OCR 요청
    POST /api/v1/submission/answers/{id}/ocr
    {
      "confidence_threshold": 0.6
    }

[2] OCR 처리 (현재 더미, 향후 실제 OCR)
    OCRService.process_ocr()
    - Tesseract 또는 Google Vision API
    - 텍스트 추출
    - processed_content 저장
    - status = COMPLETED
```

#### 방법 3: 텍스트 직접 입력 (현재 구현됨)

```
POST /api/v1/submission/answers/text
{
  "problem_id": "uuid",
  "content": "갑은 을에게 대여금을 청구할 수 있다..."
}

→ UserAnswer 생성 (status=COMPLETED)
```

**⚠️ PDF 직접 업로드**: 현재는 이미지 파일만 지원, PDF는 이미지로 변환 후 업로드 필요
**저장 위치**: `NeonDB.user_answers` 테이블

```python
    output_dir: str,      # 출력 디렉토리
    base_model_path: str, # 베이스 모델 경로
    num_epochs: int,      # 에포크 수
    batch_size: int,       # 배치 사이즈
    learning_rate: float,  # 학습률
    progress_file: str    # 진행률 파일 경로 ⭐
) -> Dict[str, Any]
```

**2. ProgressCallback** - 진행률 콜백
```python

    # epoch 종료 시 진행률 파일 저장

        progress_data = {
            "current_epoch": ...,
            "progress": ...,
            "loss": ...
        }

```

- 함수로 분리되어 API에서 직접 호출 가능

## 9. 각 도메인 역할 정리

### 9.1 Reference Domain (기준 지식)

**역할**: 문제, 모범답안, 논점 관리

**주요 엔티티**:
- `Problem`: 민사소송법 문제
- `ReferenceAnswer`: 모범답안
- `Issue`: 논점 (주논점, 부논점, 확장논점)

**저장 위치**: `NeonDB.problems`, `reference_answers`, `issues`

**사용 시점**:
- 학습 데이터 생성 시 (problem_id, reference_answer_id 참조)
- 추론 시 (모범답안과 비교)

---

### 9.2 Submission Domain (제출 답안)

**역할**: 사용자 답안 처리 및 구조화

**주요 엔티티**:
- `UserAnswer`: 사용자 답안 (텍스트 또는 이미지)
- `AnswerStructure`: 답안 구조 (문단, 문장 분리)

**주요 서비스**:
- `UserAnswerService`: 답안 CRUD
- `OCRService`: PDF/이미지 → 텍스트 변환
- `AnswerStructureService`: 답안 구조 분석

**저장 위치**: `NeonDB.user_answers`, `answer_structures`

**사용 시점**:
- 사용자 답안지 업로드 시
- 추론 시 (사용자답안과 모범답안 비교)

---

### 9.3 Reasoning Domain (추론 - HUB)

**역할**: 답안 분석의 중앙 허브

**주요 엔티티**:
- `ReasoningTask`: 추론 작업
- `ReasoningResult`: 추론 결과

**주요 서비스**:
- `ReasoningEngine`: EXAONE 모델을 활용한 답안 분석
  - `analyze_issues()`: 쟁점 분석
  - `evaluate_logic()`: 논리 평가
  - `review_expression()`: 표현 검토

**저장 위치**: `NeonDB.reasoning_tasks`, `reasoning_results`

**사용 시점**:
- 사용자 답안 첨삭 시
- 학습 완료 후 자동 첨삭 시

---

### 9.4 Feedback Domain (피드백)

**역할**: 추론 결과 → 사용자 친화적 피드백

**주요 엔티티**:
- `Feedback`: 피드백
- `FeedbackItem`: 피드백 항목 (강점, 약점, 개선안)

**주요 서비스**:
- `FeedbackGenerator`: 추론 결과로부터 피드백 생성
  - `generate_from_reasoning()`: 종합 피드백 생성

**저장 위치**: `NeonDB.feedbacks`, `feedback_items`

**사용 시점**:
- 추론 완료 후
- 사용자가 피드백 요청 시

---

### 9.5 Training Domain (학습 관리) ⭐

**역할**: 학습 데이터 및 모델 버전 관리

  - 학습 실행
  - 진행률 모니터링
  - 모델 배포
  - 자동 첨삭

**저장 위치**: `NeonDB.training_data`, `training_jobs`, `model_versions`

**사용 시점**:

## 11. 핵심 개념 정리

### 11.1 자동화의 핵심: TrainingOrchestrator (MCP Agent)

**역할**: 데이터 변경 감지 → 자동 학습 → 모델 배포

**동작 원리**:
1. 학습 데이터 입력 시 자동으로 트리거 체크
2. PENDING 데이터가 10개 이상이면 자동 학습 시작
3. 백그라운드에서 학습 실행
4. 진행률 실시간 모니터링
5. 학습 완료 시 모델 자동 배포
6. 옵션으로 자동 첨삭 실행

**비유**: 스마트 홈의 자동화 시스템
- 데이터가 쌓이면 자동으로 학습 시작
- 학습 중 진행 상황 실시간 확인
- 학습 완료 시 자동으로 새 모델 적용

---

### 11.2 약화된 스타 토폴로지

**구조**:
```
Reference → Submission → Reasoning (HUB) → Feedback
```

**특징**:
- Reasoning Domain이 중앙 허브 역할
- 도메인 간 직접 의존 최소화
- MCP를 통한 비동기 통신
- Core Layer는 모든 도메인에서 공유

---

### 11.3 MCP (Model Context Protocol)

**역할**: 도메인 간 표준화된 통신

**통신 경로**:
```
Reference ──MCP──▶ Reasoning Hub
Submission ──MCP──▶ Reasoning Hub
Reasoning Hub ──MCP──▶ Feedback
```

**장점**:
- 도메인 간 느슨한 결합
- 비동기 통신
- 확장 용이
