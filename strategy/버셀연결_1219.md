## 🎯 프로젝트 개요

### 무엇을 만들었나요?

- **프론트엔드**: Next.js 14 기반 채팅 UI (Vercel 배포)
- **백엔드**: FastAPI 기반 RAG 챗봇 API (AWS EC2 배포)
- **연결 방식**: Next.js API Routes를 통한 HTTPS 프록시

### 왜 이렇게 설계했나요?

1. **Mixed Content 문제 해결**
   - Vercel은 HTTPS로 서비스됨
   - EC2는 HTTP로 서비스 중
   - 브라우저가 HTTPS 페이지에서 HTTP 리소스를 차단 (Mixed Content 에러)
   - **해결**: Next.js API Routes가 서버 사이드에서 HTTP로 EC2 호출 → 브라우저는 HTTPS만 보므로 안전

2. **보안 강화**
   - EC2 IP를 클라이언트에 노출하지 않음
   - 서버 사이드에서만 백엔드 URL 관리
   - 환경 변수로 안전하게 관리

3. **자동 배포**
   - GitHub 푸시 시 Vercel 자동 배포
   - 프리뷰 배포로 PR 테스트 가능

### 기술 스택

- **프론트엔드**: Next.js 14, React, TypeScript
- **배포 플랫폼**: Vercel
- **백엔드**: FastAPI (EC2)
- **연결**: Next.js API Routes (프록시)

## 💻 코드 설명

### 1. API Routes 프록시 구조

#### `frontend/src/app/api/chat/rag/route.ts`

```typescript
import { NextRequest, NextResponse } from 'next/server'

// 환경 변수에서 백엔드 URL 가져오기
const BACKEND_URL = process.env.API_URL || process.env.NEXT_PUBLIC_API_URL || 'http://localhost:8000'

export async function POST(request: NextRequest) {
  try {
    const body = await request.json()

    // 환경 변수 확인
    if (!BACKEND_URL || BACKEND_URL === 'http://localhost:8000') {
      return NextResponse.json(
        { error: 'Backend URL not configured' },
        { status: 500 }
      )
    }

    // 타임아웃 설정 (60초)
    const controller = new AbortController()
    const timeoutId = setTimeout(() => controller.abort(), 60000)

    // EC2 백엔드로 요청 전달
    const response = await fetch(`${BACKEND_URL}/api/chat/rag`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(body),
      signal: controller.signal,
    })

    clearTimeout(timeoutId)

    if (!response.ok) {
      const errorText = await response.text()
      return NextResponse.json(
        { error: `Backend error: ${response.status}`, detail: errorText },
        { status: response.status }
      )
    }

    const data = await response.json()
    return NextResponse.json(data)
  } catch (error: any) {
    return NextResponse.json(
      { error: 'Failed to connect to backend server', detail: error.message },
      { status: 500 }
    )
  }
}
```

**핵심 포인트**:
- `process.env.API_URL`: 서버 사이드 환경 변수 (Vercel에 설정)
- `AbortController`: 타임아웃 처리 (60초)
- 에러 핸들링: 상세한 에러 메시지 반환

#### `frontend/src/app/api/chat/general/route.ts`

동일한 구조이지만 엔드포인트만 `/api/chat/general`로 변경

### 2. 클라이언트 코드 수정

#### Before (Mixed Content 에러 발생)

```typescript
const API_URL = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:8000'

const response = await fetch(`${API_URL}/api/chat/rag`, {
  method: 'POST',
  // ...
})
```

**문제점**:
- `NEXT_PUBLIC_API_URL`이 `http://...`로 설정되면 Mixed Content 에러 발생
- 브라우저에서 HTTP 요청을 차단

#### After (프록시 사용)

```typescript
// API_URL 제거
const endpoint = chatMode === 'rag' ? '/api/chat/rag' : '/api/chat/general'

const response = await fetch(endpoint, {  // 상대 경로 사용
  method: 'POST',
  // ...
})
```

**장점**:
- 브라우저는 HTTPS 요청만 보므로 안전
- EC2 IP가 클라이언트에 노출되지 않음
- 환경 변수 관리가 간단해짐

### 3. 환경 변수 설정

#### Vercel 환경 변수

- **Key**: `API_URL`
- **Value**: `http://43.201.10.181:8000`
- **중요**: `NEXT_PUBLIC_` 접두사 없음 (서버 사이드 전용)

**이유**:
- `NEXT_PUBLIC_` 접두사가 있으면 클라이언트 번들에 포함됨
- 서버 사이드에서만 사용하므로 접두사 불필요

## 🔍 트러블슈팅

### 문제 1: Mixed Content 에러

**증상**:
```
Mixed Content: The page at 'https://...' was loaded over HTTPS,
but requested an insecure resource 'http://...'
```

**원인**:
- Vercel은 HTTPS로 서비스
- EC2는 HTTP로 서비스
- 브라우저가 HTTPS 페이지에서 HTTP 리소스 차단

**해결**:
- Next.js API Routes로 프록시 생성
- 브라우저는 HTTPS 요청만 보므로 안전

### 문제 2: 500 Internal Server Error

**증상**:
- Network 탭에서 `/api/chat/rag` 요청이 500 에러

**가능한 원인 및 해결**:

#### 원인 1: 환경 변수 미설정

**확인 방법**:
- Vercel 로그에서 "API_URL 환경 변수가 설정되지 않았습니다" 확인

**해결**:
1. Vercel 대시보드 → Settings → Environment Variables
2. `API_URL` = `http://43.201.10.181:8000` 추가
3. 재배포

#### 원인 2: EC2 서버 다운

**확인 방법**:
```bash
# EC2에서 직접 테스트
curl http://43.201.10.181:8000/health
```

**해결**:
```bash
# EC2 서버 상태 확인
sudo systemctl status langchain-api.service

# 서비스 재시작
sudo systemctl restart langchain-api.service
```

#### 원인 3: 네트워크 차단

**확인 방법**:
- Vercel 로그에서 "Failed to connect" 에러
- 타임아웃 발생

**해결**:
1. EC2 보안 그룹 확인
   - 인바운드 규칙에 포트 8000 허용
   - 소스: `0.0.0.0/0` (또는 Vercel IP 범위)

2. 방화벽 확인
   ```bash
   sudo ufw status
   sudo ufw allow 8000
   ```

#### 원인 4: 타임아웃

**증상**:
- 504 Gateway Timeout
- 60초 후 타임아웃

**해결**:
- EC2 서버 응답 시간 확인
- 필요시 타임아웃 시간 증가 (route.ts에서 수정)

### 문제 3: CORS 에러

**증상**:
```
Access to fetch at '...' from origin '...' has been blocked by CORS policy
```

**원인**:
- EC2 FastAPI의 CORS 설정에 Vercel 도메인 미포함

**해결**:
EC2의 FastAPI 코드에서:
```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "https://your-app.vercel.app",
        "https://*.vercel.app",  # 모든 Vercel 도메인 허용
    ],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```
