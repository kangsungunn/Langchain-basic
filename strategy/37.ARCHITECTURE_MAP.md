## 🎯 주체별 역할 및 파일 매핑

### 1. 🚪 Gateway (입구)

**역할**: 모든 요청의 1차 검문소
- 규칙 기반 필터 (70-90% 처리)
- ML 보조 (모호한 10-30% 처리)
- 빠른 차단/라우팅 결정

| 파일 | 주체 | 역할 |
|------|------|------|
| `app/services/gateway/hybrid_gateway.py` | **Gateway 코어** | 규칙 엔진 + ML 보조 통합, 2단계 처리 |
| `app/services/gateway/rule_engine.py` | **규칙 엔진** | 계층적 규칙 실행 (Security → Policy → Routing) |
| `app/services/gateway/ml_assistant.py` | **ML 보조** | KoELECTRA 기반 모호한 입력 분류 |
| `app/services/gateway/rules/security_rules.py` | **Level 1: 안전장치** | 입력 검증, 인젝션 감지, Rate Limiting |
| `app/services/gateway/rules/policy_rules.py` | **Level 2: 정책** | 금칙어 체크, 부적절한 콘텐츠, URL 패턴 |
| `app/services/gateway/rules/routing_rules.py` | **Level 3: 라우팅** | 키워드/길이/패턴 기반 브랜치 선택 |

**Gateway의 출력**: `GatewayResult`
```python
GatewayResult(
    route="spam_agent",           # 라우팅 대상
    confidence=0.9,               # 신뢰도
    reason="금칙어 3개 감지",     # 근거
    method="rule_based",          # 처리 방식
    matched_rules=[...],          # 매칭된 규칙들
    latency_ms=2.5                # 지연 시간
)
```

---

### 2. ⭐ Hub Router (Star, 중앙 통제)

**역할**: 중앙 집권화 브랜치 관리
- 모든 브랜치를 관리하고 제어
- 온톨로지/정책 독점 관리
- 최종 액션 결정 (Star의 권한!)
- DB 접근 독점

| 파일 | 주체 | 역할 |
|------|------|------|
| `app/services/hub/hub_router.py` | **Hub Router 코어** | 브랜치 선택, 최종 액션 결정, 통계 관리 |
| `app/services/hub/branch_registry.py` | **브랜치 레지스트리** | 브랜치 등록/해제/조회, 메트릭 수집 |
| `app/services/hub/health_checker.py` | **헬스 체커** | 백그라운드 브랜치 헬스 체크, 자동 페일오버 |
| `app/services/hub/ontology_manager.py` | **온톨로지 관리자** | 태스크 타입 정의, 라벨 스키마, 정책 버전 관리 |

**Hub Router의 주요 메서드**:

#### `route(gateway_result, text) -> RoutingDecision`
- Gateway 결과 기반 브랜치 선택
- 브랜치 헬스 체크 및 폴백
- 라우팅 결정 반환

#### `decide_final_action(...) -> (action, reason)`
- 브랜치 권장 수신
- 온톨로지/정책 적용
- **Star가 최종 액션 결정**

**출력**: `RoutingDecision`
```python
RoutingDecision(
    branch_name="spam_agent",
    branch_config=BranchConfig(...),
    reason="게이트웨이 결과: 금칙어 감지",
    gateway_result=GatewayResult(...),
    ontology_version="1.0.0",
    fallback_used=False
)
```

---

### 3. 🔧 Branches (작업 수행자)

**역할**: Hub Router의 명령을 받아 순수 작업 수행
- 분석/처리만 담당
- **DB 접근 금지!**
- 최종 결정 권한 없음 (권장만)
- Hub Router에게 결과 반환

| 파일 | 주체 | 역할 |
|------|------|------|
| `app/services/branches/base_branch.py` | **브랜치 인터페이스** | 모든 브랜치가 따라야 할 추상 클래스 |
| `app/services/branches/spam_agent.py` | **스팸 에이전트** | EXAONE 기반 스팸 분석 (구현 완료) |
| `app/services/branches/refund_agent.py` | **환불 에이전트** | EXAONE 기반 환불 요청 처리 (향후) |
| `app/services/branches/sentiment_agent.py` | **감성 분석 에이전트** | EXAONE 기반 감성 분석 (향후) |

**브랜치의 주요 메서드**:

#### `load_model(base_model_path, adapter_path)`
- 베이스 모델 + LoRA 어댑터 로드
- GPU 메모리 관리
- 모델 캐싱

#### `process(text, context) -> BranchResult`
- 순수 분석만 수행
- **DB에 저장하지 않음!**
- Hub Router에게 결과 반환

**출력**: `BranchResult`
```python
BranchResult(
    branch_name="spam_agent",
    task_type="spam",
    label="spam",                      # 라벨
    confidence=0.85,                   # 신뢰도
    recommended_action="block",        # 권장 액션 (Hub Router가 최종 결정)
    reasoning="URL_MISMATCH 및 URGENT_MONEY 패턴 감지",
    evidence=["URL_MISMATCH", "URGENT_MONEY"],
    latency_ms=150.5,
    metadata={...}
)
```

## 🔄 전체 데이터 흐름 (요청부터 응답까지)

### Phase 1: Gateway (입구)

```
1. 사용자 입력 (FastAPI Endpoint)
   │
   ├─> app/router/mcp_router.py
   │   └─> POST /api/mcp/filter
   │
   └─> app/services/gateway/hybrid_gateway.py
       │
       ├─> Level 1: SecurityRules (안전장치)
       │   ├─> 입력 검증 (빈 입력, 길이 초과, 인코딩)
       │   ├─> 인젝션 패턴 감지
       │   ├─> Rate Limiting
       │   └─> 의심스러운 문자 체크
       │   └─> ❌ reject → 즉시 반환
       │
       ├─> Level 2: PolicyRules (명시적 정책)
       │   ├─> 스팸 금칙어 체크
       │   ├─> 환불 키워드 체크
       │   ├─> 감성 키워드 체크
       │   ├─> 부적절한 콘텐츠
       │   └─> 의심스러운 URL 패턴
       │   └─> ❌ reject 또는 ✅ route="spam_agent"
       │
       ├─> Level 3: RoutingRules (브랜치 라우팅)
       │   ├─> 키워드 기반 라우팅
       │   ├─> 길이 기반 라우팅
       │   └─> 패턴 기반 라우팅
       │   └─> ✅ route="spam_agent" (확실) 또는 ⚠️ ml_assist_required
       │
       └─> ML Assistant (모호한 10-30%만)
           ├─> KoELECTRA 모델 추론
           └─> ✅ route="spam_agent" (신뢰도 0.5~0.8)

출력: GatewayResult
```

### Phase 2: Hub Router (중앙 통제)

```
2. Hub Router (Star)
   │
   ├─> app/services/hub/hub_router.py
   │   │

   │   │   │
   │   │   ├─> 브랜치 상태 확인 (active?)
   │   │   │   └─> ❌ inactive → fallback_routing() → default_agent
   │   │   │
   │   │   ├─> 브랜치 헬스 체크 (health_checker)
   │   │   │   └─> ❌ unhealthy → fallback_routing() → default_agent
   │   │   │
   │   │   └─> ✅ 정상 라우팅 결정
   │   │       └─> RoutingDecision(branch_name="spam_agent", ...)
   │   │
   │   └─> SpamAgent 호출 (브랜치 실행)

출력: RoutingDecision
```

```
3. SpamAgent (브랜치)
   │
   ├─> app/services/branches/spam_agent.py
   │   │
   │   ├─> process(text, context)
   │   │   │

   │   │   ├─> 결과 분석
   │   │   │   ├─> evidence 개수 → 신뢰도 계산
   │   │   │   ├─> label 결정 (spam/suspicious/ham)
   │   │   │   └─> recommended_action (block/quarantine/deliver)
   │   │   │
   │   │   └─> BranchResult 생성
   │   │       └─> ⚠️ DB에 저장하지 않음! Hub Router에게 반환
```

### Phase 4: Hub Router (최종 결정)

```
4. Hub Router (Star의 권한)
   │
   ├─> app/services/hub/hub_router.py
   │   │
   │   ├─> BranchResult 수신
   │   │
   │   ├─> decide_final_action(...)
   │   │   │
   │   │   ├─> 온톨로지 정책 로드 (ontology_manager)
   │   │   │   └─> spam 정책: {auto_block_threshold: 3, quarantine_threshold: 1}
   │   │   │
   │   │   ├─> 브랜치 신뢰도 체크
   │   │   │   └─> confidence < 0.7 → "quarantine" (보수적 판단)
   │   │   │
   │   │   ├─> 증거 개수 기반 정책 적용
   │   │   │   ├─> evidence_count >= 3 → branch_recommendation 따름 (block)
   │   │   │   ├─> evidence_count >= 1 → Star 판단: block → quarantine
   │   │   │   └─> evidence_count == 0 → Star 판단: deliver
   │   │   │
   │   │   └─> return (final_action, policy_reason)
   │   │
   │   └─> DB 저장 (다음 Phase에서 구현)
   │       ├─> 입력 텍스트 저장
   │       ├─> BranchResult 저장
   │       ├─> RoutingLog 저장
   │       └─> ⭐ Star만 DB 접근 가능!

출력: (final_action, policy_reason)
```

## 🔑 핵심 원칙 (Star Topology)

### 1. 중앙 집권화 (Centralization)

| 주체 | 권한 | 금지 |
|------|------|------|
| **Hub Router (Star)** | ✅ 모든 브랜치 관리<br>✅ 온톨로지/정책 독점<br>✅ 최종 액션 결정<br>✅ DB 접근 독점 | - |
| **Branch (작업 수행자)** | ✅ 분석/처리 수행<br>✅ 권장 액션 제안 | ❌ DB 접근<br>❌ 최종 결정<br>❌ 다른 브랜치 호출 |
| **Gateway (입구)** | ✅ 1차 필터링<br>✅ 빠른 차단 | ❌ DB 접근<br>❌ 브랜치 직접 호출 |

### 2. 역할 분리 (Separation of Concerns)

```
Gateway (입구)
   └─> 70-90% 빠른 처리 (규칙 기반)
   └─> 10-30% ML 보조 (모호한 케이스)

Hub Router (Star, 중앙 통제)
   └─> 브랜치 선택 및 관리
   └─> 온톨로지/정책 적용
   └─> 최종 액션 결정
   └─> DB 저장

Branch (작업 수행자)
   └─> 순수 분석/처리
   └─> BranchResult 반환
   └─> DB 접근 금지!
```

### 3. 데이터 흐름 (Unidirectional Flow)

```
User Input
   ↓
Gateway (GatewayResult)
   ↓
Hub Router (RoutingDecision)
   ↓
Branch (BranchResult)
   ↓
Hub Router (final_action, DB 저장)
   ↓
User Response
```

## 📊 성능 특성

| 구간 | 지연 시간 | 처리 비율 | 비고 |
|------|-----------|-----------|------|
| **Gateway (규칙 기반)** | 1-5ms | 70-90% | 대부분의 요청 처리 |
| **Gateway (ML 보조)** | 50-100ms | 10-30% | 모호한 케이스만 |
| **Hub Router** | 1-3ms | 100% | 브랜치 선택 |
| **Branch (EXAONE)** | 100-200ms | 라우팅됨 | GPU 추론 |
| **전체 (평균)** | 20-50ms | - | 규칙 비율에 따라 달라짐 |

## 📝 용어 정리

| 용어 | 의미 |
|------|------|
| **Star** | Hub Router의 별칭, 중앙 통제 센터 |
| **Branch** | 작업 수행자 (예: SpamAgent, RefundAgent) |
| **Gateway** | 1차 검문소, 빠른 필터링 |
| **Ontology** | 태스크 타입, 라벨 스키마, 정책 정의 |
| **Policy** | 최종 액션 결정 기준 (임계값, 규칙) |
| **BranchResult** | 브랜치가 Hub Router에게 반환하는 결과 |
| **RoutingDecision** | Hub Router가 내린 브랜치 선택 결정 |
| **GatewayResult** | Gateway가 Hub Router에게 전달하는 라우팅 정보 |
