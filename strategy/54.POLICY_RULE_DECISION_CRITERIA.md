# 🎯 정책/규칙 판단 기준 (민사소송법 서술형 답안지 첨삭 시스템)

## 📋 개요

민사소송법 서술형 답안지 첨삭 시스템에서 **정책 기반**과 **규칙 기반**을 구분하는 명확한 기준을 정의합니다.

---

## 🔍 판단 기준

### ✅ 정책 기반 (Policy-Based) → Star 토폴로지

**특징**: 복잡한 비즈니스 로직, ML 모델 필요, 여러 도메인 간 협업

**판단 기준**:
1. **ML 모델 추론이 필요한 작업**
   - 답안 분석 (쟁점 분석, 논리 평가, 표현 검토)
   - 종합 분석 (여러 분석 통합)
   - 피드백 생성 (ML 기반)

2. **복잡한 비즈니스 로직**
   - 여러 도메인 간 협업이 필요한 작업
   - 조건부 처리 및 복잡한 분기 로직
   - 실시간 의사결정이 필요한 작업

3. **Star 토폴로지가 필요한 작업**
   - Reasoning Hub를 통한 중앙 집중식 처리
   - 여러 Agent 간 협업

### ✅ 규칙 기반 (Rule-Based) → Direct Service

**특징**: 단순 CRUD 작업, 규칙 기반 처리 가능

**판단 기준**:
1. **단순 데이터 조작**
   - 데이터 생성 (CREATE)
   - 데이터 조회 (READ)
   - 데이터 수정 (UPDATE)
   - 데이터 삭제 (DELETE)

2. **규칙 기반 처리**
   - 단순 파싱 (구조 분석, PDF 파싱)
   - 파일 업로드/저장
   - 상태 변경

3. **직접 서비스 호출 가능**
   - 별도의 오케스트레이션 없이 처리 가능
   - 단일 도메인 내에서 완결

## 📊 API 엔드포인트 분류

### 정책 기반 (Policy-Based) → Star 토폴로지

#### Reasoning Domain
- ✅ `POST /reasoning/analyze/issues` - 쟁점 분석
  - **이유**: ML 모델(EXAONE) 사용, 복잡한 분석 로직
- ✅ `POST /reasoning/analyze/logic` - 논리 평가
  - **이유**: ML 모델 사용, 논리적 일관성 평가
- ✅ `POST /reasoning/analyze/expression` - 표현 검토
  - **이유**: ML 모델 사용, 표현 품질 평가
- ✅ `POST /reasoning/analyze/comprehensive` - 종합 분석
  - **이유**: 여러 분석 통합, ML 모델 사용, 복잡한 비즈니스 로직

#### Feedback Domain
- ✅ `POST /feedback/generate` - 피드백 생성
  - **이유**: ML 기반 피드백 생성, Reasoning 결과 활용

#### Training Domain
- ✅ `POST /training/jobs` - 학습 작업 생성 및 시작
  - **이유**: 복잡한 ML 학습 프로세스, 여러 단계 오케스트레이션

### 규칙 기반 (Rule-Based) → Direct Service

#### Training Domain
- ✅ `POST /training/data` - 학습 데이터 생성
  - **이유**: 단순 CRUD 작업
- ✅ `POST /training/data/pdf` - PDF에서 학습 데이터 추출
  - **이유**: 단순 파싱 작업 (규칙 기반)
- ✅ `GET /training/data` - 학습 데이터 조회
  - **이유**: 단순 조회 작업
- ✅ `GET /training/jobs` - 학습 작업 조회
  - **이유**: 단순 조회 작업

#### Submission Domain
- ✅ `POST /submission/answers/text` - 텍스트 답안 생성
  - **이유**: 단순 CRUD 작업
- ✅ `POST /submission/answers/image` - 이미지 답안 생성
  - **이유**: 단순 파일 저장 작업
- ✅ `GET /submission/answers` - 답안 목록 조회
  - **이유**: 단순 조회 작업
- ✅ `POST /submission/answers/{id}/analyze` - 구조 분석
  - **이유**: 단순 파싱 작업 (규칙 기반)
- ⚠️ `POST /submission/answers/{id}/ocr` - OCR 처리
  - **현재**: 규칙 기반 (더미 구현)
  - **향후**: 정책 기반으로 변경 가능 (실제 OCR 엔진 사용 시)

#### Reasoning Domain
- ✅ `GET /reasoning/tasks` - 작업 목록 조회
  - **이유**: 단순 조회 작업
- ✅ `GET /reasoning/tasks/{id}` - 작업 조회
  - **이유**: 단순 조회 작업
- ✅ `POST /reasoning/tasks` - 작업 생성
  - **이유**: 단순 CRUD 작업

#### Reference Domain
- ✅ 모든 엔드포인트 (CRUD 작업)
  - **이유**: 참조 답안 관리, 단순 CRUD

## 🤖 KoELECTRA 판단 프롬프트 구성

### 프롬프트 템플릿

```python
def build_decision_prompt(domain: str, action: str, request_summary: str) -> str:
    """
    정책/규칙 판단을 위한 프롬프트 구성
    """
    prompt = f"""
다음은 민사소송법 서술형 답안지 첨삭 시스템의 API 요청입니다.

**도메인**: {domain}
**액션**: {action}
**요청 요약**: {request_summary}

이 요청을 처리하기 위해:
1. ML 모델(EXAONE 등) 추론이 필요한가요?
2. 복잡한 비즈니스 로직이나 여러 도메인 간 협업이 필요한가요?
3. Star 토폴로지(Reasoning Hub)를 통한 중앙 집중식 처리가 필요한가요?

위 질문 중 하나라도 "예"라면 → **정책 기반 (policy)**
모두 "아니오"라면 → **규칙 기반 (rule)**

답변: [policy 또는 rule]
"""
    return prompt
```

### 프롬프트 예시

#### 예시 1: 정책 기반 (종합 분석)
```
도메인: reasoning
액션: comprehensive_analysis
요청 요약: 사용자 답안의 쟁점 분석, 논리 평가, 표현 검토를 종합적으로 수행

→ 정책 기반 (ML 모델 필요, 복잡한 분석 로직)
```

#### 예시 2: 규칙 기반 (학습 데이터 생성)
```
도메인: training
액션: create_training_data
요청 요약: 문제 텍스트, 모범답안 텍스트, 사용자 답안 텍스트를 데이터베이스에 저장

→ 규칙 기반 (단순 CRUD 작업)
```

#### 예시 3: 정책 기반 (피드백 생성)
```
도메인: feedback
액션: generate
요청 요약: 분석 결과를 바탕으로 사용자에게 개선 방향을 제시하는 피드백 생성

→ 정책 기반 (ML 기반 피드백 생성, 복잡한 비즈니스 로직)
```

#### 예시 4: 규칙 기반 (답안 조회)
```
도메인: submission
액션: get_answers
요청 요약: 저장된 사용자 답안 목록을 페이지네이션하여 조회

→ 규칙 기반 (단순 조회 작업)
```

## 🎯 DecisionMaker 구현 전략

### 1단계: 규칙 기반 사전 필터링

```python
# 빠른 판단을 위한 규칙 기반 사전 필터링
RULE_BASED_ACTIONS = {
    "training": ["create_training_data", "get_training_data", "get_training_jobs"],
    "submission": ["create_text_answer", "create_image_answer", "get_answers"],
    "reasoning": ["get_tasks", "get_task", "create_task"],
    "reference": ["*"],  # 모든 액션
}

POLICY_BASED_ACTIONS = {
    "reasoning": ["analyze_issues", "analyze_logic", "analyze_expression", "comprehensive_analysis"],
    "feedback": ["generate"],
    "training": ["start_training", "create_training_job"],
}
```

### 2단계: KoELECTRA 모델 판단

```python
# 규칙 기반 사전 필터링을 통과한 경우에만 KoELECTRA 사용
if action in RULE_BASED_ACTIONS.get(domain, []):
    return "rule"
elif action in POLICY_BASED_ACTIONS.get(domain, []):
    return "policy"
else:
    # 모호한 경우 KoELECTRA로 판단
    prompt = build_decision_prompt(domain, action, request_summary)
    result = koelectra.predict(prompt)
    return result["strategy"]
```
