# 🎯 정책/규칙 기반 오케스트레이터 구현 전략

## 📋 목표

라우터에서 받은 요청을 오케스트레이터가 KoELECTRA 모델을 사용하여 정책/규칙 기반으로 판단하여:
- **정책 기반** → Star 토폴로지 (Reasoning Hub)
- **규칙 기반** → 일반 서비스 (Direct Service)

로 분기하는 시스템 구현

---

## 🏗️ 전체 아키텍처

```
[프론트엔드]
    ↓ HTTP 요청
[라우터 Layer] (app/api/v1/*.py)
    ↓ 요청 전달
[오케스트레이터] (app/core/orchestration/workflow_manager.py)
    ↓ KoELECTRA로 정책/규칙 판단
    ├─ 정책 기반 → [Star 토폴로지] (Reasoning Hub)
    └─ 규칙 기반 → [일반 서비스] (Direct Service)
```

### ✅ Step 3: 전략 패턴 구현

#### 3.1 BaseStrategy 인터페이스

**파일**: `app/core/orchestration/strategies/base_strategy.py`

```python
from abc import ABC, abstractmethod
from typing import Any
from sqlalchemy.ext.asyncio import AsyncSession

class RoutingStrategy(ABC):
    """라우팅 전략 인터페이스"""

    @abstractmethod
    async def route(
        self,
        domain: str,
        action: str,
        request: Any,
        session: AsyncSession
    ) -> Any:
        """요청 라우팅"""
        pass
```

#### 3.2 PolicyStrategy 구현

**파일**: `app/core/orchestration/strategies/policy_strategy.py`

**역할**: 정책 기반 요청 → Reasoning Hub (Star 토폴로지)

```python
class PolicyStrategy(RoutingStrategy):
    """정책 기반 전략 → Star 토폴로지"""

    async def route(self, domain, action, request, session):
        from app.domain.reasoning.orchestrators.reasoning_hub import ReasoningHub

        hub = ReasoningHub(session)
        return await hub.process(domain, action, request)
```

#### 3.3 RuleStrategy 구현

**파일**: `app/core/orchestration/strategies/rule_strategy.py`

**역할**: 규칙 기반 요청 → 일반 서비스 직접 호출

```python
class RuleStrategy(RoutingStrategy):
    """규칙 기반 전략 → 일반 서비스"""

    async def route(self, domain, action, request, session):
        # 도메인별 서비스 매핑
        service_map = {
            "training": TrainingDataService,
            "reference": ReferenceAnswerService,
            "submission": UserAnswerService,
            # ...
        }

        service_class = service_map.get(domain)
        service = service_class(session)
        method = getattr(service, action)
        return await method(request)
```

### ✅ Step 4: WorkflowManager 구현

**파일**: `app/core/orchestration/workflow_manager.py`

**역할**: 중앙 오케스트레이터

**기능**:
1. DecisionMaker로 정책/규칙 판단
2. 전략 선택 (PolicyStrategy 또는 RuleStrategy)
3. 선택된 전략으로 라우팅 실행

```python
class WorkflowManager:
    """중앙 오케스트레이터"""

    def __init__(self, session: AsyncSession):
        self.session = session
        self.decision_maker = DecisionMaker()
        self.strategies = {
            "policy": PolicyStrategy(),
            "rule": RuleStrategy()
        }

    async def process_request(
        self,
        domain: str,
        action: str,
        request: Any
    ) -> Any:
        # 1. 정책/규칙 판단
        strategy_type = await self.decision_maker.determine_strategy(
            domain, action, request
        )

        # 2. 전략 선택 및 실행
        strategy = self.strategies[strategy_type]
        return await strategy.route(domain, action, request, self.session)
```

### ✅ Step 5: 라우터 연동 (점진적)

#### 5.1 테스트용 라우터 수정

**파일**: `app/api/v1/training.py`

**변경 전**:
```python
@router.post("/data")
async def create_training_data(data: TrainingDataCreate, ...):
    service = TrainingDataService(session)
    return await service.create(data)
```

**변경 후**:
```python
@router.post("/data")
async def create_training_data(data: TrainingDataCreate, ...):
    from app.core.orchestration.workflow_manager import WorkflowManager

    orchestrator = WorkflowManager(session)
    return await orchestrator.process_request(
        domain="training",
        action="create_training_data",
        request=data
    )
```

- `app/api/v1/submission.py` → 규칙 기반 (Direct)
- `app/api/v1/reference.py` → 규칙 기반 (Direct)
