```python
RULE_BASED_ACTIONS = {
    "training": ["create_training_data", "get_training_data", "get_training_jobs", "get_training_data_list"],
    "submission": ["create_text_answer", "create_image_answer", "get_answers", "get_answer", "analyze_structure"],

```
- ✅ **휴리스틱 기반**: 사전 정의된 규칙 목록으로 빠른 판단
- ✅ **명시적 규칙 매칭**: 도메인과 액션 조합으로 직접 매칭

#### 2단계: 정책 기반 사전 필터링 (휴리스틱)
```python
POLICY_BASED_ACTIONS = {
    "reasoning": ["analyze_issues", "analyze_logic", "analyze_expression", "comprehensive_analysis"],
    "feedback": ["generate", "generate_from_reasoning", "generate_report"],
    "training": ["start_training", "create_training_job"],
}
```
- ✅ **휴리스틱 기반**: 사전 정의된 규칙 목록으로 빠른 판단
- ✅ **명시적 규칙 매칭**: 도메인과 액션 조합으로 직접 매칭

#### 3단계: KoELECTRA 모델 판단 (ML 기반, 휴리스틱적)
```python
# 모호한 경우에만 KoELECTRA 사용
prompt = self._build_prompt(domain, action, request)
result = self.koelectra.predict(prompt)
```
- ✅ **ML 모델 사용**: KoELECTRA로 텍스트 분류
- ⚠️ **휴리스틱적 특성**: 프롬프트 기반 판단, 확률적 결정
- ✅ **폴백 메커니즘**: 모델 실패 시 규칙 기반으로 폴백

## 🎯 결론

### ✅ **휴리스틱 기반으로 구현되어 있음**

**근거**:

1. **사전 필터링 (1-2단계)**: 
   - 명시적인 규칙 목록(`RULE_BASED_ACTIONS`, `POLICY_BASED_ACTIONS`)을 사용
   - 도메인과 액션 조합으로 직접 매칭
   - **이것은 전형적인 휴리스틱 접근법입니다**

2. **KoELECTRA 모델 (3단계)**:
   - 모호한 경우에만 사용
   - 프롬프트 기반 판단 (규칙 기반 프롬프트)
   - 확률적 결정 (softmax 확률)
   - **ML 모델이지만 휴리스틱적 특성을 가집니다**

3. **폴백 메커니즘**:
   - KoELECTRA 실패 시 규칙 기반으로 폴백
   - 안전한 기본값 제공
   - **휴리스틱의 안전장치 역할**

    ├─ 프롬프트 구성
    ├─ KoELECTRA 추론
    └─ 확률 기반 판단 → "policy" 또는 "rule" 반환 ✅
    ↓ (실패 시)

    └─ "rule" 반환 ✅

## 💡 휴리스틱의 정의

**휴리스틱(Heuristic)**: 
- 경험적 규칙이나 근사 알고리즘
- 완벽한 해결책이 아닌 실용적인 해결책
- 빠른 판단을 위한 단순화된 규칙

**현재 구현의 휴리스틱 특성**:
1. ✅ **사전 정의된 규칙 목록**: 명시적 매칭 규칙
2. ✅ **경험적 판단 기준**: 도메인 전문가의 경험 기반 분류
3. ✅ **빠른 판단**: 대부분의 경우 1-2단계에서 결정
4. ✅ **폴백 메커니즘**: 안전한 기본값 제공
