  - 역할 분리로 더 명확한 구조

### 4. 프롬프트 기반 판단

  - 도메인, 액션, 요청 데이터를 포함한 프롬프트

## 🔍 상세 비교

### 강사님 예제 구조
```
PlayerRouter
  ↓
PlayerOrchestrator
  ├─ KoELECTRA 모델 로딩
  ├─ _determine_strategy_type() (KoELECTRA 판단)
  └─ 전략 선택 및 실행
      ├─ PolicyBasedStrategy → PlayerAgent
      └─ RuleBasedStrategy → PlayerService
```

### 현재 구현 구조
```
Router (app/api/v1/*.py)
  ↓
WorkflowManager (오케스트레이터)
  ├─ DecisionMaker
  │   ├─ KoELECTRA 로더 (싱글톤)
  │   ├─ _build_prompt() (프롬프트 구성)
  │   └─ determine_strategy() (KoELECTRA 판단)
  └─ 전략 선택 및 실행
      ├─ PolicyStrategy → ReasoningHub (Star 토폴로지)
      └─ RuleStrategy → Direct Service
```
