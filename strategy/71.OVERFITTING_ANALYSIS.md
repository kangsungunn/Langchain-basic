# 🔍 오버피팅 분석 가이드

## 📋 개요

**목적**: 더미 데이터로 학습한 모델의 오버피팅 여부를 확인하고, 실제 데이터로 학습할 때의 주의사항을 파악합니다.

---

## ✅ 현재 상황

### 더미 데이터 학습 결과
- **학습 데이터**: 158개
- **검증 데이터**: 19개
- **테스트 데이터**: 21개
- **에폭 수**: 3
- **학습 방식**: Full Fine-tuning

### 오버피팅 위험 요소
1. **데이터 양이 적음**: 158개는 매우 적은 양
2. **더미 데이터 특성**: 실제 패턴과 다를 수 있음
3. **에폭 수**: 3 에폭은 적절하지만, 데이터가 적으면 오버피팅 가능

---

## 🔍 오버피팅 확인 방법

### 1. 학습 로그 확인

**스크립트 실행**:
```bash
python training/orchestration/check_overfitting.py --model-dir artifacts/models/finetuned/koelectra-policy-rule
```

**확인 사항**:
- 학습 손실 vs 검증 손실
- 검증 손실이 증가하는 추세인지
- 손실 차이 (검증 - 학습)가 큰지

### 2. 오버피팅 지표

**오버피팅 징후**:
- ✅ 검증 손실이 학습 손실보다 훨씬 큼 (차이 > 0.3)
- ✅ 검증 손실이 증가하는 동안 학습 손실이 감소
- ✅ 검증 손실이 지속적으로 증가하는 추세

**정상 상태**:
- ✅ 학습 손실과 검증 손실이 비슷하게 감소
- ✅ 검증 손실이 안정적이거나 감소

## 📊 예상 결과

### 더미 데이터 학습의 경우

**예상 시나리오 1: 오버피팅 없음**
- 더미 데이터가 단순하여 모델이 쉽게 학습
- 검증 손실이 학습 손실과 비슷
- 하지만 실제 데이터에서는 성능이 낮을 수 있음

**예상 시나리오 2: 오버피팅 있음**
- 더미 데이터가 적어서 모델이 특정 패턴에 과적합
- 검증 손실이 학습 손실보다 큼
- 실제 데이터에서 성능 저하 예상

## 🎯 실제 데이터로 학습할 때의 주의사항

### 1. 데이터 양

**최소 권장량**:
- 학습 데이터: 500개 이상
- 검증 데이터: 100개 이상
- 테스트 데이터: 100개 이상

**이유**: 더 많은 데이터는 오버피팅을 방지하고 일반화 성능을 향상시킵니다.

### 2. 에폭 수 조정

**더미 데이터 (158개)**:
- 에폭 수: 3 (적절)

**실제 데이터 (500개 이상)**:
- 에폭 수: 5-10 (데이터 양에 따라 조정)
- Early stopping 사용 권장

### 3. 정규화 강화

**학습률 조정**:
- 더미 데이터: `2e-5` (기본값)
- 실제 데이터: `1e-5` 또는 `2e-5` (데이터 양에 따라)

**Weight Decay**:
- 현재: `0.01`
- 오버피팅 시: `0.1`로 증가 고려

**드롭아웃**:
- 모델에 드롭아웃 레이어 추가 고려

### 4. Early Stopping

**사용 권장**:
- 검증 손실이 증가하기 시작하면 학습 중단
- `load_best_model_at_end=True` (이미 설정됨)

## 🔧 오버피팅 방지 전략

### 1. 데이터 증강 (Data Augmentation)

**방법**:
- 프롬프트 변형 (동의어 교체, 문장 순서 변경)
- 도메인/액션 조합 다양화

**주의**: 텍스트 분류에서는 제한적

### 2. 교차 검증 (Cross-Validation)

**방법**:
- K-fold 교차 검증 (K=5)
- 더 안정적인 성능 평가

### 3. LoRA 사용

**장점**:
- 파라미터 수 감소 → 오버피팅 위험 감소
- 학습 속도 향상
- 메모리 사용량 감소

**사용 방법**:
```bash
python training/orchestration/train_koelectra_policy_rule.py \
    --data-dir training/data/policy_rule_classification \
    --output-dir artifacts/models/finetuned/koelectra-policy-rule \
    --num-epochs 5 \
    --use-lora
```

### 4. 학습/검증 손실 모니터링

**실시간 모니터링**:
- TensorBoard 사용
- 학습 중 손실 추이 확인

**조기 중단**:
- 검증 손실이 2-3 에폭 연속 증가 시 중단
