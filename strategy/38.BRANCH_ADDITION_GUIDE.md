# 브랜치 추가 가이드

새로운 브랜치(에이전트)를 Star Topology에 추가하는 방법을 설명합니다.

## 📌 브랜치란?

브랜치는 **Hub Router(Star)의 명령을 받아 특정 작업을 수행하는 독립적인 작업 수행자**입니다.

### ⚠️ 중요 원칙

1. **순수 작업 수행자**: 분석/처리만 담당
2. **DB 접근 금지**: Hub Router만 DB 접근 가능
3. **최종 결정 권한 없음**: 권장만 가능, Hub Router가 최종 결정
4. **Hub Router에게 결과 반환**: `BranchResult` 객체로 반환

def check_refund_policy(text: str) -> RuleResult:
    """환불 정책 체크"""

            decision="route_to_refund",

## 🗂️ 파일 위치 요약

| 단계 | 파일 | 역할 | 주체 |
|------|------|------|------|
| 1 | `app/services/branches/<branch_name>.py` | 브랜치 구현 | **브랜치 (작업 수행자)** |
| 2 | `app/services/hub/ontology_manager.py` | 온톨로지 등록 | **Hub Router (Star)** |
| 3 | `app/services/hub/branch_registry.py` | 브랜치 레지스트리 등록 | **Hub Router (Star)** |
| 4 | `app/services/gateway/rules/*.py` | 라우팅 규칙 추가 | **Gateway (입구)** |
| 5 | `app/services/hub/hub_router.py` | 최종 액션 결정 로직 | **Hub Router (Star)** |

## 📊 데이터 흐름 (브랜치 추가 후)

```
1. 사용자 입력
   └─> Gateway (hybrid_gateway.py)
       ├─> 규칙 기반 필터 (rule_engine.py)
       │   └─> 환불 키워드 감지 → route="refund_agent"
       └─> ML 보조 (ml_assistant.py)
           └─> 모호한 경우만

2. Hub Router (hub_router.py)
   ├─> 브랜치 선택 (route="refund_agent")
   ├─> 브랜치 헬스 체크 (health_checker.py)
   └─> RefundAgent 호출 (refund_agent.py)

3. RefundAgent (브랜치)
   ├─> 모델 추론 (EXAONE + LoRA)
   ├─> BranchResult 생성
   └─> Hub Router에게 반환 (DB 저장 안함!)

4. Hub Router (Star의 권한)
   ├─> BranchResult 수신
   ├─> 온톨로지/정책 적용 (ontology_manager.py)
   ├─> 최종 액션 결정 (approve/reject/manual_review)
   └─> DB 저장 (db_save_node) ⭐ Star만 가능!

5. 사용자에게 응답
```

## 📝 주의사항

1. **브랜치는 DB에 저장하지 않습니다!**
   - Hub Router (Star)만 DB 접근 가능
   - 브랜치는 `BranchResult`만 반환

2. **최종 액션은 Hub Router가 결정합니다!**
   - 브랜치는 `recommended_action`만 제공
   - Hub Router가 온톨로지/정책 적용하여 최종 결정

3. **브랜치는 순수 작업 수행자입니다!**
   - 분석/처리만 담당
   - 외부 API 호출, 파일 저장 등은 Hub Router를 통해

4. **어댑터 경로는 정확히 입력하세요!**
   - 학습 완료된 어댑터 경로를 `BranchConfig`에 등록
   - 경로가 틀리면 헬스 체크에서 `unhealthy` 상태로 표시
