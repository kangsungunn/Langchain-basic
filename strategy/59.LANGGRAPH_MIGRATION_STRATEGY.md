# 🔄 LangGraph 전환 전략 (휴리스틱 → LangGraph)

## 📋 전략 개요

**목표**: 휴리스틱 기반 오케스트레이터를 LangGraph로 전환
- 데이터 입력 완료 후 (예: JSONL 4개 입력 완료)
- 오케스트레이터만 LangGraph로 전환
- 기존 Agent/Service/Repository는 유지
- 외부 인터페이스(API)는 변경 없음

**핵심 원칙**: 최소 침투, 점진적 전환

### 현재 오케스트레이터 동작 방식

1. **WorkflowManager** (`app/core/orchestration/workflow_manager.py`)
   - 요청 수신
   - DecisionMaker로 정책/규칙 판단
   - 전략 선택 (PolicyStrategy 또는 RuleStrategy)
   - 선택된 전략으로 라우팅

2. **전략 패턴 (GoF)**
   - `PolicyStrategy` → ReasoningHub (Star 토폴로지)
   - `RuleStrategy` → Direct Service 호출

3. **ReasoningHub** (`app/domain/reasoning/orchestrators/reasoning_hub.py`)
   - 정책 기반 요청 처리
   - 도메인별 분기 처리 (reasoning, feedback, training)

#### 3. LangGraph 그래프 (`app/core/orchestration/graph.py`)

**새로 생성**: `app/core/orchestration/graph.py`

```python
"""LangGraph 워크플로우 그래프"""
from langgraph.graph import StateGraph, END
from .models.states.workflow_state import WorkflowState
from .nodes import (
    validate_node,
    determine_strategy_node,
    policy_process_node,
    rule_process_node,
    finalize_node,
    route_strategy
)

def build_workflow_graph() -> StateGraph:
    """워크플로우 그래프 빌드"""
    graph = StateGraph(WorkflowState)

    # 노드 추가
    graph.add_node("validate", validate_node)
    graph.add_node("determine_strategy", determine_strategy_node)
    graph.add_node("policy_process", policy_process_node)
    graph.add_node("rule_process", rule_process_node)
    graph.add_node("finalize", finalize_node)

    # 엣지 추가
    graph.set_entry_point("validate")
    graph.add_edge("validate", "determine_strategy")
    graph.add_conditional_edges(
        "determine_strategy",
        route_strategy,
        {
            "policy": "policy_process",
            "rule": "rule_process"
        }
    )
    graph.add_edge("policy_process", "finalize")
    graph.add_edge("rule_process", "finalize")
    graph.add_edge("finalize", END)

    return graph.compile()
```

### 수정할 파일

#### 1. `app/core/orchestration/workflow_manager.py`

**변경 전** (전략 패턴):
```python
class WorkflowManager:
    def __init__(self, session: AsyncSession):
        self.session = session
        self.decision_maker = DecisionMaker()
        self.strategies = {
            "policy": PolicyStrategy(),
            "rule": RuleStrategy()
        }

    async def process_request(self, domain, action, request):
        strategy_type = await self.decision_maker.determine_strategy(...)
        strategy = self.strategies.get(strategy_type)
        return await strategy.route(...)
```

**변경 후** (LangGraph):
```python
from langgraph.graph import StateGraph
from .graph import build_workflow_graph
from .models.states.workflow_state import WorkflowState

class WorkflowManager:
    def __init__(self, session: AsyncSession):
        self.session = session
        self.graph = build_workflow_graph()

    async def process_request(self, domain, action, request):
        # 초기 상태 생성
        initial_state = WorkflowState(
            domain=domain,
            action=action,
            request=request
        )

        # LangGraph 실행
        final_state = await self.graph.ainvoke(initial_state)

        return final_state.result
```

## 🎯 핵심 구현 포인트

### 1. 상태 관리
- LangGraph StateGraph는 상태를 자동으로 관리
- 각 노드는 상태를 받아서 수정하고 반환
- 상태는 TypedDict 또는 Pydantic 모델로 정의

### 2. 조건부 라우팅
- `add_conditional_edges` 사용
- `route_strategy` 함수로 분기 결정
- DecisionMaker의 판단 결과를 상태에 저장

### 3. 기존 코드 재사용
- DecisionMaker는 그대로 사용 (노드에서 호출)
- ReasoningHub는 그대로 사용 (노드에서 호출)
- Agent/Service는 그대로 사용 (노드에서 호출)

### 4. 에러 처리
- 각 노드에서 try-except로 에러 처리
- 에러는 상태에 저장하고 다음 노드로 전달
- 최종 노드에서 에러 반환
