# 피드백 학습 데이터 수집·활용 가이드

## 개요

사용자가 **첨삭 결과 페이지**에서 남긴 "정정" / "추가·강조" 의견은 **학습용 데이터**로 저장됩니다.
이 데이터로 나중에 모델을 개선할 수 있습니다.

- **정정(correction)**: "이 부분은 틀렸다", "이렇게 피드백 내려라"
- **추가·강조(addition)**: "이런 포인트를 더 넣어라", "이걸 강조해서 내려라"

## 수집 경로

1. 사용자가 답안 업로드 → 첨삭 결과 확인
2. 결과 페이지 하단 **"이 첨삭 결과에 대한 의견 (모델 개선용)"**에서
   - 유형 선택 (정정 / 추가·강조)
   - 의견 내용 입력 후 **의견 보내기**

데이터는 DB 테이블 `feedback_corrections`에 저장됩니다.

## DB·API

- **테이블**: `feedback_corrections`
  - `id`, `feedback_id`, `correction_type` (correction | addition), `content`, `created_at`, `meta`
- **API**
  - `POST /api/v1/feedback/feedbacks/{feedback_id}/corrections` — 의견 저장
  - `GET /api/v1/feedback/feedbacks/{feedback_id}/corrections` — 해당 피드백의 의견 목록

## 학습용 내보내기

수집된 의견을 JSONL로 내보내려면:

```bash
# .env에 DATABASE_URL 설정 후
python scripts/export_feedback_corrections.py
# 기본 출력: data/feedback_corrections.jsonl

# 출력 경로 지정
python scripts/export_feedback_corrections.py --out data/my_corrections.jsonl

# SFT 형식 (instruction / input / output)으로 저장
python scripts/export_feedback_corrections.py --format sft --out training/data/feedback_corrections_sft.jsonl
```

- **raw**: 한 줄당 한 건, `feedback_id`, `correction_type`, `content`, `feedback_summary` 등 원본 필드
- **sft**: instruction + input(원래 피드백 요약) + output(사용자 의견) 형태로, 나중에 "사용자 의견을 반영한 피드백 생성" SFT에 사용 가능

## 활용 방향

1. **SFT**: `--format sft`로 내보낸 JSONL을 사용해, "원래 피드백 + 사용자 정정/추가 요청 → 수정된 피드백" 생성 모델 학습
2. **RAG**: 정정/추가 요청을 임베딩해 두고, 새 피드백 생성 시 유사 사례를 검색해 참고
3. **규칙/휴리스틱**: 자주 나오는 정정 패턴을 분석해 규칙으로 반영

마이그레이션: `alembic upgrade head` 실행 후 `feedback_corrections` 테이블이 생성됩니다.
