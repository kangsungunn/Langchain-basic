## 2. 다음에 할 일 (순서)

### 2-1. 학습 데이터를 모델 입력 형식으로 변환

- **목적**: ExaOne SFT(지시 학습)에 넣을 수 있게 **instruction / input / output** 형태로 만듦.
- **방법**: `scripts/problem_issues_to_sft_jsonl.py` 실행 (아래에서 추가).
- **결과**: 예) `data/raw/civil_procedure/problem_issues/gy_saeryejip_sft.jsonl`
  - 한 줄: `{"instruction": "...", "input": "문제 지문", "output": "논점1\n논점2\n..."}` 또는 채팅 형식.

### 2-2. ExaOne 논점 추출용 파인튜닝 ✅ 준비됨

- **목적**: "문제 지문만 넣으면 큰 논점 목록이 나오는" 모델 만들기.
- **입력**: 2-1에서 만든 SFT용 JSONL을 **train/val로 분할**한 데이터 (`training/data/issue_extraction/`).
- **준비**:
  1. SFT JSONL 생성: `python scripts/problem_issues_to_sft_jsonl.py`
  2. train/val 분할: `python scripts/split_sft_train_val.py`
     → `training/data/issue_extraction/train.jsonl`, `val.jsonl` 생성
- **학습 스크립트**: `training/shared/train_exaone_lora.py` (ExaOne Causal LM + LoRA, 답변 부분만 loss).
- **실행 (프로젝트 루트에서)**:
  ```bash
  python -m training.shared.train_exaone_lora --data-dir training/data/issue_extraction --output-dir artifacts/models/finetuned/exaone-issue-extraction
  ```
- **출력**: LoRA 어댑터가 `artifacts/models/finetuned/exaone-issue-extraction/` 에 저장됨.

### 2-3. 논점 추출 서비스/API 하나 만들기 ✅ 완료

- **구현**: `app/domain/v1/minso/spokes/services/issue_extraction_service.py`
  - `extract_issues_from_problem(problem_content)` → `List[str]` (학습된 ExaOne LoRA 사용, 지연 로딩)
  - 베이스: `artifacts/models/base/exaone-2.4b`, 어댑터: `artifacts/models/finetuned/exaone-issue-extraction`
- **노출**: MCP 툴 `extract_issues_from_problem` (중앙 MCP 서버에 등록됨)

### 2-4. 자동화에 붙이기 (analyze-and-feedback) ✅ 완료

- **동작**: `POST .../analyze-and-feedback` 호출 시
  - 해당 문제의 **모범답안이 있으면** → 기존처럼 모범답안 기준으로 종합 추론·피드백.
  - **모범답안이 없으면** → 문제 지문으로 논점 추출 → 추출된 논점 목록으로 쟁점 분석·피드백 생성.
- **조건**: 모범답안이 없을 때는 **문제(problem)가 DB에 있고 content가 있어야** 논점 추출 가능. 문제가 없거나 지문이 비면 400.
