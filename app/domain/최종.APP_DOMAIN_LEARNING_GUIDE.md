# app/domain 학습 가이드 — 구조·흐름·기능·역할

> **현재** app/domain 폴더의 확정 구조를 바탕으로 한 이론 위주 학습용 정리.
> Star 토폴로지 통합·레거시 폴더 제거·core→domain 오케스트레이션 이전을 반영한 **최종 상태** 설명.
> core 가이드보다 **더 자세히** 서술.

---

## 1. 개요

### 1.1 domain의 위치와 원칙

`app/domain`은 **비즈니스 로직·엔티티·오케스트레이션**을 담당하는 레이어다.

- **역할**: 민사소송법(minso) 서브도메인의 **Star 토폴로지** 구현. Hub(중앙 조율)·Spokes(말단 처리)·Models(엔티티·DTO)·Shared(공통)로 구성.
- **의존 방향**: API(`app/api`)가 domain을 **사용**한다. domain은 **core**(DB, ML 로더, 로거)를 사용하며, **api를 import하지 않는다**.
- **Training**: 학습 데이터·작업·모델 버전은 **minso 밖** 루트 `training/` 패키지에서만 관리한다. minso 내부에 training 폴더·서비스는 없다.

### 1.2 Star 토폴로지 요약

| 폴더 | 역할 (이론) | minso에서의 실제 |
|------|-------------|------------------|
| **hub/** | 중앙: 조율·라우팅·집약 리포지토리 | 정책/규칙 판단(DecisionMaker), MinsoHub·ReasoningHub, 리포지토리, MCP, 라우팅 스텁 |
| **spokes/** | 말단: 실제 비즈니스·인프라 | 도메인별 서비스(Reference, Submission, Reasoning, Feedback), 에이전트·인프라 스텁 |
| **models/** | 엔티티·상태·DTO | bases(ORM), transfers(Pydantic DTO), states·enums 스텁 |
| **shared/** | 도메인 공통 | 예외, 값 객체, 도메인 이벤트 |

- **의존성 원칙**: hub → spokes, models, shared 사용. spokes → **hub 참조 금지**, models, shared만 사용. models → shared·core만. shared → 다른 도메인 폴더 참조 금지.

### 1.3 레거시 폴더 제거 (Phase 5 완료)

- **feedback/, reasoning/, reference/, submission/** 폴더는 **삭제 완료**.
  코드는 hub/repositories, hub/orchestrators, spokes/services, models/bases, models/transfers 등으로 이전됨.
- **training** 도메인은 minso가 아닌 **루트 training/** 패키지**만** 사용. `app/domain/training` 없음.
- API·테스트는 `hub`, `spokes`, `models`, `shared` 경로로만 import.

## 3. Hub (중앙) — 상세

Hub는 **요청 진입·정책/규칙 판단·라우팅·리포지토리(데이터 접근)** 를 담당한다. Spokes를 **호출**만 하고, Spokes는 Hub를 참조하지 않는다.

### 3.1 decision_maker.py — 정책/규칙 판단

- **역할**: 요청이 **정책 기반**인지 **규칙 기반**인지 판단. core의 KoELECTRA 로더를 **사용**만 하고, 판단 로직(비즈니스)은 domain에 둠.
- **입력**: `domain`, `action`, `request` (요청 데이터).
- **출력**: `"policy"` 또는 `"rule"`.
- **판단 순서**:
  1. **사전 필터(규칙)**: `RULE_BASED_ACTIONS`에 (domain, action)이 있으면 → `"rule"`.
  2. **사전 필터(정책)**: `POLICY_BASED_ACTIONS`에 있으면 → `"policy"`.
  3. **KoELECTRA**: 위에 없으면 KoELECTRA로 분류. 실패 시 기본값 `"rule"`.
- **의존**: `app.core.ml.koelectra_loader`, `app.core.utils.logger`. domain 내부는 shared만 필요 시 사용.

### 3.2 orchestrators/minso_hub.py — 중앙 허브 (진입점)

- **역할**: API에서 호출하는 **단일 진입점**. `process(domain, action, request)` 로 받아, DecisionMaker로 정책/규칙 판단 후 분기.
- **정책** → `_handle_policy()` → **ReasoningHub**로 위임 (현재는 ReasoningHub만 구현).
- **규칙** → `_handle_rule()` → **Spokes 서비스** 직접 호출.
  서비스 매핑(`_get_service_map`)과 액션→메서드 매핑(`action_mapping`)으로 해당 서비스 인스턴스를 만들고 메서드 호출.
- **서비스 매핑**: training → TrainingDataService(루트 training), submission → UserAnswerService, reasoning → ReasoningTaskService, feedback → FeedbackService.
  reference는 API에서 직접 서비스를 쓰므로 MinsoHub 서비스 맵에는 없음.
- **의존**: DecisionMaker, ReasoningHub, shared(DomainValidationError), core(logger). Spokes 서비스 클래스는 lazy import로 순환 방지.

### 3.3 orchestrators/reasoning_orchestrator.py — ReasoningHub

- **역할**: **정책 기반** 요청만 처리. domain=reasoning(쟁점/논리/표현/종합 분석), domain=feedback(피드백 생성·리포트)를 Spokes 서비스(ReasoningEngine, FeedbackGenerator)로 위임.
- **process(domain, action, request)**:
  - reasoning → `_handle_reasoning()`: analyze_issues, analyze_logic, analyze_expression, comprehensive_analysis → ReasoningEngine 호출.
  - feedback → `_handle_feedback()`: generate, generate_from_reasoning, generate_report → FeedbackGenerator 호출.
- **의존**: spokes.services.reasoning_service(ReasoningEngine), spokes.services.feedback_service(FeedbackGenerator), shared(DomainValidationError), core(logger). **Hub는 Spokes만 호출.**

### 3.4 orchestrators 기타 (feedback, reference, submission, chat)

- **현재**: 파일만 있고 내용 없음(스텁). 정책 처리 확장 시 여기에 구현.
  MinsoHub는 정책이면 **ReasoningHub**로만 보내고, ReasoningHub가 reasoning/feedback 액션을 처리.

### 3.5 repositories/ — 데이터 접근 단일 소스

- **역할**: CRUD·집약 조회. **models(bases)** 만 참조. 도메인 엔티티에 대한 영속화 경계.
- **구성**:
  - **feedback_repository.py**: FeedbackRepository, FeedbackItemRepository.
  - **reference_repository.py**: ProblemRepository, ReferenceAnswerRepository, IssueRepository.
  - **submission_repository.py**: UserAnswerRepository, AnswerStructureRepository.
  - **reasoning_repository.py**: ReasoningTaskRepository, ReasoningResultRepository.
- **Training**: 리포지토리는 루트 `training/` 패키지에 있음. hub에는 training_repository 없음.
- **의존**: `app.domain.v1.minso.models`(bases), core(database). **Spokes 서비스가 이 리포지토리들을 사용.**

### 3.6 mcp_central/ — MCP (Model Context Protocol)

- **역할**: 도메인 간 통신 프로토콜 정의. **core/mcp에서 domain/hub으로 이전**됨.
- **구성**: protocol(MCPProtocol, DomainType, MessageType, MCPErrorCode), message(MCPRequest, MCPResponse, MCPError, MCPEvent), transport(MCPTransport, get_mcp_transport).
- **사용처**: 현재는 테스트 등 소수. 실제 API·첨삭 흐름에서는 미사용. 필요 시 도메인 간/외부 연동에서 사용.

### 3.7 routing/

- **현재**: `__init__.py`만 있음(스텁). 요청 분기·분류 로직을 넣을 자리.
  현재 분류는 DecisionMaker에서 수행.

## 4. Spokes (말단) — 상세

Spokes는 **실제 비즈니스 로직·외부 호출**을 수행한다. **Hub를 import하지 않는다.** Hub의 repositories·models·shared만 사용.

### 4.1 services/ — 도메인별 서비스

- **reference_service.py**
  - **ProblemService**: 문제 CRUD, 목록/조회.
  - **ReferenceAnswerService**: 모범답안 CRUD, 문제별 답안 조회.
  - **IssueService**: 논점 CRUD, 모범답안별 논점 조회, extract_issues_from_answer(더미).
  - **의존**: hub.repositories(Problem, ReferenceAnswer, Issue), models, models.transfers, shared.

- **submission_service.py**
  - **UserAnswerService**: 텍스트/이미지 답안 생성, 조회, 수정, 삭제.
  - **AnswerStructureService**: 구조 분석, 문단/문장 분해.
  - **OCRService**: OCR(더미) 등.
  - **의존**: hub.repositories(UserAnswer, AnswerStructure), models, models.transfers, shared.

- **reasoning_service.py**
  - **ReasoningTaskService**: 추론 작업 CRUD, 목록/조회.
  - **ReasoningEngine**: 쟁점 분석(analyze_issues), 논리 평가(evaluate_logic), 표현 검토(review_expression), 종합 분석(comprehensive_analysis).
    **core/ml**(ModelLoader, InferenceEngine) 사용.
  - **의존**: hub.repositories(ReasoningTask, ReasoningResult), models, models.transfers, shared, core.ml, core.utils.logger.

- **feedback_service.py**
  - **FeedbackService**: 피드백 CRUD, 목록/조회.
  - **FeedbackGenerator**: generate_from_reasoning, generate_report. Reasoning 결과를 활용한 피드백 생성.
  - **의존**: hub.repositories(Feedback, FeedbackItem, ReasoningTask, ReasoningResult), models, models.transfers, shared.

- **Training**: 학습 데이터·작업 서비스는 **루트 training/services** 에 있음. MinsoHub가 규칙 기반일 때 해당 서비스를 lazy import하여 사용.

### 4.2 agents/, infrastructure/

- **현재**: agents는 파일만 있고 내용 없음. infrastructure는 `__init__.py`만 있음(스텁).
  추론 에이전트·OCR 등 인프라 확장 시 채울 자리.

## 5. Models — 상세

Models는 **엔티티(ORM)·DTO(Transfer)·상태·Enum** 을 한 곳에서 관리한다. **비즈니스 흐름은 포함하지 않는다.**

### 5.1 bases/ — ORM 엔티티 (단일 소스)

- **역할**: DB 테이블과 매핑되는 엔티티. **core.database**의 Base·Mixin만 상속.
- **구성**:
  - **feedback.py**: FeedbackType, FeedbackSeverity, Feedback, FeedbackItem.
  - **reference.py**: Problem, ReferenceAnswer, Issue.
  - **submission.py**: SubmissionType, SubmissionStatus, UserAnswer, AnswerStructure.
  - **reasoning.py**: TaskType, TaskStatus, ReasoningTask, ReasoningResult.
- **Training**: TrainingData, TrainingJob, ModelVersion 등은 **루트 training/models** 에만 있음.
- **의존**: `app.core.database`(Base, TimestampMixin 등). 다른 domain 레이어(hub, spokes) 참조 금지.

### 5.2 transfers/ — DTO (Data Transfer Object)

- **역할**: API 요청/응답·레이어 간 전달용 Pydantic 모델. **Schema 대신 Transfer** 로 통일.
- **구성**: 도메인별 `*_transfer.py` (feedback_transfer, reference_transfer, submission_transfer, reasoning_transfer).
  Create/Update/Response/ListResponse, Request/Response 쌍 등.
- **사용처**: API 라우터(요청 바디·응답 모델), Hub·Spokes(메서드 인자·반환 타입).
- **의존**: Pydantic. ORM 변환은 `from_orm()` 등으로 서비스·라우터에서 수행. models.bases를 직접 참조할 필요는 없고, 같은 models 패키지 내에서만 구분용으로 씀.

### 5.3 states/, enums/

- **states**: LangGraph 등 워크플로우 상태(TypedDict)를 둘 자리. 현재 파일만 있고 스텁.
- **enums**: 공통 Enum을 둘 자리. 현재는 각 bases/transfers에 Enum이 정의되어 있고, enums/는 스텁.

## 6. Shared — 상세

도메인 전역에서 쓰는 **예외·값 객체·이벤트** 를 둔다. Hub/Spokes/Models가 공통으로 사용.

### 6.1 exceptions.py

- **MinsoDomainError**: minso 공통 기본 예외. API에서 4xx/5xx 변환 시 사용.
- **EntityNotFoundError**: 엔티티 부재(404 대응). `entity_type`, `entity_id`. ValueError 상속으로 기존 `except ValueError` 호환.
- **DomainValidationError**: 비즈니스 규칙·검증 위반(400 등). ValueError 상속.
- **사용처**: Spokes 서비스·리포지토리에서 raise. API에서 catch 후 HTTPException으로 변환.

### 6.2 value_objects.py

- **EntityId**: NewType(str). 식별자 타입 힌트용.
- **ENTITY_***: 엔티티 종류 상수("user_answer", "reasoning_task" 등). EntityNotFoundError의 entity_type 등에 사용.

### 6.3 events.py

- **역할**: 도메인 이벤트 정의(UserAnswerCreated, ReasoningTaskCompleted, FeedbackGenerated, TrainingJobStarted 등).
  발생·구독은 향후 구현. 현재는 스텁 수준.

## 7. 데이터·제어 흐름 (현재)

### 7.1 API → Domain (전체)

1. **HTTP 요청** → `app/api/v1/minso/*.py` 라우터.
2. **세션**: `get_session`(core/database) Depends.
3. **진입점**: 라우터가 **MinsoHub(session).process(domain, action, request)** 호출.
4. **MinsoHub**:
   - **DecisionMaker.decide(domain, action, request)** → "policy" | "rule".
   - **policy** → ReasoningHub.process(domain, action, request) → ReasoningEngine / FeedbackGenerator 호출.
   - **rule** → 해당 Spokes 서비스 인스턴스 생성 후 action에 해당하는 메서드 호출(예: UserAnswerService.create_text_answer).
5. **Spokes 서비스**: hub.repositories로 CRUD, models(bases·transfers) 사용, 필요 시 core(ml, logger) 사용. shared 예외 사용.
6. **응답**: Transfer(Pydantic) 또는 ORM → from_orm 등으로 반환. API가 response_model으로 직렬화.

### 7.2 Reference 도메인 (규칙만, Hub 경유 안 함)

- **설계**: reference는 **모든 액션이 규칙 기반**이고, API에서 **직접** ProblemService, ReferenceAnswerService, IssueService를 호출.
- **MinsoHub 서비스 맵**에는 reference를 넣지 않음. API 라우터가 `from app.domain.v1.minso.spokes.services.reference_service import ...` 로 서비스를 부름.

### 7.3 Training 도메인 (minso 밖)

- **학습 데이터·작업**은 **루트 training/** 패키지. MinsoHub가 규칙일 때만 `training.services.TrainingDataService` 등을 lazy import하여 사용.
- **import**: `from training.services import TrainingDataService` 등. `app.domain.v1.minso` 안에는 training 폴더가 없음.

## 8. 의존성 방향 검증 (학습용 체크리스트)

- **API** → domain: spokes.services, models.transfers 위주. hub.orchestrators(MinsoHub) 사용. models.bases 직접 참조 없음.
- **Hub** → spokes, models, shared, core(필요 시). **Spokes 참조 금지** → Hub만 Spokes를 부름.
- **Spokes** → hub.repositories, models(bases·transfers), shared, core(ml, logger). **hub.orchestrators 참조 금지.**
- **models.bases** → core.database만.
- **models.transfers** → Pydantic만(도메인 내부 다른 레이어 불필요).
- **shared** → 다른 도메인 폴더 참조 금지.

## 10. 학습 시 참고할 원칙 정리

1. **Star 토폴로지**: Hub는 중앙(조율·판단·라우팅·리포지토리), Spokes는 말단(실제 처리). Hub → Spokes 호출, Spokes → Hub 미참조.
2. **정책/규칙 판단은 domain**: DecisionMaker는 hub에 두고, KoELECTRA 로더만 core에서 사용. 오케스트레이션·MCP도 domain(hub)에 있음.
3. **단일 소스**: 엔티티는 models/bases, DTO는 models/transfers. 레거시 feedback/reasoning/reference/submission 폴더 없음.
4. **Training은 minso 밖**: 학습 데이터·작업·모델은 루트 `training/` 만. MinsoHub가 규칙일 때 해당 서비스만 lazy import.
5. **Reference는 API 직접 호출**: 규칙만 있으므로 API가 직접 Reference Spokes 서비스를 부름. MinsoHub 경유 선택 사항 아님.
6. **Transfer = DTO**: Schema 대신 Transfer 명칭 통일. Pydantic으로 API·레이어 간 계약.
7. **Shared**: 예외·값 객체·이벤트는 shared에만 두고, Hub/Spokes/Models가 공통 사용.
