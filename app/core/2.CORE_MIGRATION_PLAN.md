# app/core 구조 변경 계획 (강사 구조 대비)

> `1.APP_CORE_STRUCTURE.md`(강사 구조)와 **현재 app/core**를 비교하고,
> 직접 작업 가능한 부분과 단계별 전략을 정리한 문서.
> **아직 코드 수정은 하지 않고**, 판단·결정이 필요한 부분은 문단 끝에 질문으로 표시.

---

## 1. 구조 비교 요약

### 1.1 강사 구조(목표)에만 있는 것

| 항목 | 강사 문서 역할 | 현재 |
|------|----------------|------|
| **core/database.py** (파일) | 호환성 레이어. `from app.core.database import ...` 리다이렉트용. | ❌ 없음 (이전 정리 시 제거됨) |
| **core/korean_embeddings.py** | 한국어 임베딩 초기화 (OpenAI / HF 선택). | ❌ 없음 |
| **core/korean_llm.py** | 한국어 LLM 초기화 (Ollama / HF, 레거시 경로). | ❌ 없음 |
| **core/langsmith_config.py** | LangSmith 추적 설정. | ❌ 없음 |
| **core/llm/** | LLM 추상화·팩토리 (base, factory, providers: openai, korean_hf_local, exaone_local, midm_local). | ❌ 없음 |
| **core/rag_chain.py** | RAG 체인 생성 (vectorstore + LLM 주입). | ❌ 없음 |
| **core/vectorstore.py** | PGVector + 임베딩 (get_vectorstore, 샘플 문서 등). | ❌ 없음 |
| **database/session.py** | 강사 문서에는 **connection.py 없음**. session에 engine, get_db, init/close 등 일체 기술. | 현재는 **connection.py + session.py** 분리 |

### 1.2 현재 core에만 있는 것 (강사 문서에 없음)

| 항목 | 현재 역할 | 사용처 |
|------|------------|--------|
| **core/database/connection.py** | DB 연결 싱글톤 (DatabaseConnection, get_database, engine). | database/session.py, alembic, main.py, domain bases, training/models |
| **core/mcp/** | MCP 프로토콜·핸들러·전송. | test_phase0.py 만 |
| **core/ml/** | ModelLoader, InferenceEngine, KoELECTRALoader (분류/추론). | domain reasoning_service, training/services, decision_maker, 테스트 |
| **core/orchestration/** | WorkflowManager, DecisionMaker, 노드·전략 (정책/규칙 라우팅). | api/v1/minso (feedback, reasoning, submission, training), training/orchestration, 테스트 |
| **core/utils/** | logger, pdf_parser, test_data_factory, validators, converters. | api, domain, training, orchestration, ml 전반 |

### 1.3 양쪽 다 있는 것 (역할 비교)

| 항목 | 강사 구조 | 현재 | 비고 |
|------|-----------|------|------|
| **config.py** | Pydantic BaseSettings, DB/LLM/LangSmith/Redis/JWT 등. | Settings 클래스, class 변수, load_from_env. DB/API/ML/MCP. | 강사는 Pydantic 권장. 현재는 class 변수. |
| **database/** | base, mixin, **session**(engine·get_db·init/close 일체). | base, mixin, **connection** + session. | 강사는 connection 없이 session 한 파일에 연결+세션. |
| **__init__.py** | 패키지 표시. | (비어 있음). | 동일 유지 가능. |

## 2. 직접 하실 수 있는 작업 (폴더/파일 생성·정리)

코드 내용을 넣지 않고 **폴더와 빈(또는 최소) 파일만** 만드는 단계입니다.

  → **직접**: `app/core/database.py` 파일 생성만 해 두기.

- **core/korean_embeddings.py**
  - 파일 생성.
  → **직접**: 빈 파일 또는 `# TODO: init_korean_embeddings()` 주석만.

- **core/korean_llm.py**
  - 파일 생성.
  → **직접**: 빈 파일 또는 `# TODO: init_korean_llm()` 주석만.

- **core/langsmith_config.py**
  - 파일 생성.
  → **직접**: 빈 파일 또는 `# TODO: get_langsmith_config()` 주석만.

- **core/rag_chain.py**
  - 파일 생성.
  → **직접**: 빈 파일 또는 `# TODO: create_rag_chain()` 주석만.

- **core/vectorstore.py**
  - 파일 생성.
  → **직접**: 빈 파일 또는 `# TODO: get_vectorstore()` 주석만.

  - 패키지로 두고, 강사 문서 트리대로 **폴더·빈 파일**만 만듦.

  - 강사 문서에는 없지만, api/domain/training에서 사용 중.
  → **직접**: 폴더/파일 삭제나 이동 없이 유지.

## 3. 단계별 전략 (작업 순서 제안)

### Phase 0: 결정 사항 정리 (질문에 답한 뒤 진행)

- 아래 **§4 질문**에 대해 “유지 / 제거 / 통합 / 나중에” 등을 정해 두면, 그에 맞춰 Phase 1~3을 조정할 수 있습니다.

### Phase 1: 강사 구조 “자리” 만들기 (직접 작업 가능)

1. **core 루트 파일 생성**
   - `database.py`, `korean_embeddings.py`, `korean_llm.py`, `langsmith_config.py`, `rag_chain.py`, `vectorstore.py`
   - 내용은 비우거나 TODO 주석만.

2. **core/llm/ 트리 생성**
   - `llm/__init__.py`, `llm/base.py`, `llm/factory.py`
   - `llm/providers/__init__.py`, `providers/openai.py`, `korean_hf_local.py`, `exaone_local.py`, `midm_local.py`
   - 모두 빈 파일 또는 역할 1줄 주석.

3. **database.py**
   - `from app.core.database import Base, get_session, ...` 가 동작하도록,
     패키지 `database/`의 `__init__.py`를 re-export하는 **한 줄짜리 호환 레이어**로 채우기.
   - (선택) 이 단계에서 할지, Phase 2에서 할지만 정하면 됨.

### Phase 2: 기존 코드와의 연결 (구현·import 정리)

1. **config**
   - 강사 구조에 맞게 Pydantic `BaseSettings`로 옮길지,
     현재 `Settings`를 유지하면서 필드만 추가할지 결정 후 적용.

2. **database**
   - `connection.py` 유지 시: 강사 문서의 “session 안에 다 넣는” 방식은 **참고만** 하고,
     현재처럼 connection + session 분리 유지해도 됨.
   - `database.py`(파일)는 Phase 1에서 만든 호환 레이어만 채우면 됨.

3. **llm / korean_embeddings / vectorstore / rag_chain**
   - 실제 구현은 이 단계에서.
   - 기존 `ml/`(ModelLoader, InferenceEngine, KoELECTRA)와 역할이 다르면 **공존**시키는 선에서 정리.

### Phase 3: 정리·문서화

1. **1.APP_CORE_STRUCTURE.md**
   - “이 프로젝트에서는 여기에 다음이 추가되어 있음” 식으로
     `mcp/`, `ml/`, `orchestration/`, `utils/` 한 줄씩 정리.

2. **CORE_CLEANUP_SUMMARY.md**
   - 강사 구조 도입 후 정리한 내용 반영.

## 4. 판단이 필요한 부분 (질문)

다음은 **강사 구조와 현재 프로젝트를 어떻게 맞출지** 결정이 필요한 부분입니다. 선택지만 제시하므로, 방향만 정해 주시면 그에 맞춰 다음 단계(코드/문서 수정)를 제안하겠습니다.

### Q1. orchestration / mcp / utils

- **강사 문서**에는 `orchestration/`, `mcp/`, `utils/`가 없습니다.
- **현재**: api, domain, training, ml 등에서 사용 중입니다.

**선택지:**

- **A)** 그대로 `app/core` 안에 유지 (강사 구조 + 프로젝트 전용 영역으로 둠).
- **B)** `orchestration`만 `app/` 직하 또는 다른 레이어로 이동하고, core에는 config/database/llm/embeddings/vectorstore/rag 위주만 둠.
- **C)** mcp/utils는 유지, orchestration만 이동 등 **일부만 재배치**.

→ 원하시는 쪽을 알려주시면 됩니다.

---

### Q2. ml/ vs llm/ + korean_embeddings + vectorstore

- **강사 구조**: `llm/`(LLM 팩토리), `korean_embeddings.py`, `vectorstore.py` (RAG/임베딩).
- **현재**: `ml/` 안에 ModelLoader, InferenceEngine, KoELECTRALoader (분류·추론용).

**역할 차이:**

- 강사 구조의 llm/embeddings/vectorstore → **RAG·채팅용 LLM/임베딩**.
- 현재 ml/ → **KoELECTRA 등 분류·추론 모델**.

**선택지:**

- **A)** 강사 구조를 **추가**만 하고, `ml/`은 그대로 둠 (RAG용 llm/vectorstore와 분류용 ml 공존).
- **B)** 나중에 RAG를 쓰지 않으면 `llm/`, `vectorstore.py`, `rag_chain.py`는 빈/스텁만 두고, `ml/`만 실제 구현 유지.
- **C)** `ml/`을 점진적으로 `llm/` 또는 다른 이름으로 흡수·통합 (구체 단계는 결정 후 제안).

→ 원하는 방향(A/B/C 또는 변형)을 알려주시면 됩니다.

---

### Q3. database/connection.py vs 강사 문서의 “session 한 파일”

- **강사 문서**: `database/` 아래에 `session.py`만 있고, engine·get_db·init/close를 session에 다 적는 구조. **connection.py 없음**.
- **현재**: `connection.py`(싱글톤·engine) + `session.py`(세션 팩토리·get_session)로 분리.

**선택지:**

- **A)** **현재 구조 유지**. connection.py 그대로 두고, 강사 문서는 “우리 프로젝트는 connection + session 분리”로 해석.
- **B)** 나중에 **session.py 한 파일로 통합** (connection 역할을 session 안으로 이전).
  → 이 경우 기존 `from app.core.database.connection import ...` 사용처를 한 번에 바꿔야 하므로, Phase 2 이후로 두는 것이 좋습니다.

→ A/B 중 선호하시는 쪽을 알려주시면 됩니다.

---

### Q4. config: Pydantic BaseSettings vs 현재 Settings

- **강사 문서**: Pydantic `BaseSettings`로 환경 변수 로드.
- **현재**: `Settings` 클래스 + class 변수 + `load_from_env()`.

**선택지:**

- **A)** 당분간 **현재 Settings 유지**. 강사 구조 도입 시 필요한 필드만 추가 (예: llm_provider, openai_api_key, local_model_dir 등).
- **B)** **Pydantic BaseSettings로 전환**. 한 번에 바꾸거나, 새 설정 파일을 만들고 점진적으로 이전.

→ A/B 중 선호하시는 쪽을 알려주시면 됩니다.
