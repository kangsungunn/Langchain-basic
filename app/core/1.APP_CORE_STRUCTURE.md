# app/core 폴더 구조 및 역할 정리

> MCP 스타 토폴로지 구조의 **핵심 레이어** 참조 문서.  
> 개인 프로젝트에서 주제/데이터만 바꾸고 동일한 구조를 맞추기 위한 가이드.

---

## 1. 개요

`app/core`는 **설정·DB·LLM·임베딩·RAG·벡터스토어** 등 애플리케이션 전역에서 쓰는 공통 인프라를 담당합니다.  
도메인(`app/domain`)이나 API(`app/api`)는 이 레이어에 의존하고, **core는 다른 앱 레이어에 직접 의존하지 않도록** 유지하는 것이 원칙입니다.

```
app/
├── core/          ← 이 문서의 대상 (설정, DB, LLM, 임베딩, RAG, 벡터스토어)
├── api/           ← core를 사용
├── domain/        ← core를 사용
└── main.py
```

---

## 2. 디렉터리/파일 트리

```
app/core/
├── __init__.py
├── config.py              # 중앙 설정 (Pydantic Settings)
├── database.py            # DB 호환성 레이어 (기존 코드용 리다이렉트)
├── database/              # DB 패키지
│   ├── __init__.py
│   ├── base.py            # SQLAlchemy Base
│   ├── mixin.py           # TimestampMixin, SoftDeleteMixin, StatusMixin
│   └── session.py         # 비동기 엔진/세션, get_db, init/close
├── korean_embeddings.py   # 한국어 임베딩 초기화 (HF / OpenAI 선택)
├── korean_llm.py          # 한국어 LLM 초기화 (Ollama / HuggingFace 선택)
├── langsmith_config.py    # LangSmith 추적 설정
├── llm/                   # LLM 추상화 및 팩토리
│   ├── __init__.py
│   ├── base.py            # LLM 타입 정의 (LLMType)
│   ├── factory.py          # 설정 기반 LLM 생성 (create_llm_from_config)
│   └── providers/         # LLM 구현체
│       ├── __init__.py
│       ├── openai.py      # OpenAI Chat
│       ├── korean_hf_local.py  # 로컬 HF 한국어
│       ├── exaone_local.py     # EXAONE-2.4B 로컬
│       └── midm_local.py      # Midm-2.0-Mini-Instruct 로컬
├── rag_chain.py           # RAG 체인 생성 (LLM 주입 가능)
└── vectorstore.py        # PGVector + 임베딩 (Neon/Postgres)
```

## 3. 파일/폴더별 역할

### 3.1 루트

| 파일 | 역할 |
|------|------|
| `__init__.py` | 패키지 표시. `"""Core 모듈."""` 정도만 유지. |
| `config.py` | **중앙 설정**. Pydantic `BaseSettings`로 환경 변수 로드. DB URL, Postgres 개별 필드, 디버그, 포트, LangSmith, Upstash Redis, JWT TTL 등. `database_url`은 `DATABASE_URL` 우선, 없으면 `POSTGRES_*` 조합. `_sanitize_database_url`로 psycopg2/asyncpg에 맞지 않는 쿼리 옵션 제거. 전역 `settings` 인스턴스 제공. |
| `database.py` | **호환성 레이어**. `app.core.database` 패키지로 리다이렉트. `Base`, 믹스인들, `engine`, `AsyncSessionLocal`, `get_db`, `init_database`, `check_migration_status`, `close_database`, `create_database_engine` 등을 재export. 기존에 `from app.core.database import ...` 쓰던 코드를 그대로 두기 위함. |

### 3.2 database/

| 파일 | 역할 |
|------|------|
| `__init__.py` | `Base`, 믹스인, 세션 관련 심볼 export. Alembic 실행 중일 때는 `session` import를 하지 않고 session 관련을 `None`으로 두어 asyncpg 의존을 피함. |
| `base.py` | SQLAlchemy **DeclarativeBase** 한 개. 모든 도메인 모델의 부모. 도메인 간 직접 의존 없이 공통 기능은 믹스인으로 제공. |
| `mixin.py` | **TimestampMixin** (created_at/updated_at), **SoftDeleteMixin** (deleted_at, is_deleted), **StatusMixin** (status, activate/deactivate/suspend, is_active). 도메인 모델에서 선택적으로 상속. |
| `session.py` | **비동기 DB 연결**. `create_database_engine()`로 `postgresql+asyncpg` URL 생성, Neon 등 외부 Postgres 시 SSL 처리. 전역 `engine`, `AsyncSessionLocal`. FastAPI용 `get_db()` 제너레이터. `init_database()`(연결/마이그레이션 테이블 존재 확인), `check_migration_status()`(alembic_version fail-fast), `close_database()`. SQLite 테스트 시 `StaticPool` 등 처리. |

### 3.3 llm/

| 파일 | 역할 |
|------|------|
| `__init__.py` | `LLMType`, `create_llm_from_config` export. LLM은 RAG 등에서 이 패키지를 통해 주입. |
| `base.py` | **LLM 타입**. `LLMType = BaseLanguageModel` (LangChain). RAG/도메인에서 주입받는 LLM의 공통 타입. |
| `factory.py` | **설정 기반 LLM 생성**. `create_llm_from_config(settings)` → `settings.llm_provider`에 따라 `openai` / `korean_local` / `midm` 등 분기. OpenAI는 `openai_api_key`, 로컬은 `local_model_dir` 사용. 지원하지 않는 provider면 `ValueError`. (※ `config.Settings`에 `llm_provider`, `openai_api_key`, `local_model_dir` 등이 없으면 추가 필요.) |
| `providers/__init__.py` | provider 팩토리 함수들 export (`create_openai_chat_llm`, `create_midm_local_llm`, `create_midm_instruct_llm` 등). |
| `providers/openai.py` | `create_openai_chat_llm(model_name, temperature, **kwargs)` → `ChatOpenAI` 인스턴스. |
| `providers/korean_hf_local.py` | `create_local_korean_llm(model_dir)` → 로컬 HuggingFace 한국어 모델 (transformers pipeline + HuggingFacePipeline). 4bit 양자화 옵션. |
| `providers/exaone_local.py` | `create_exaone_local_llm(model_dir)` → EXAONE-2.4B 로컬. `ExaoneLocalLLM` 래퍼 클래스(프롬프트 포맷 등) 포함. |
| `providers/midm_local.py` | `create_midm_local_llm(model_dir)`, `create_midm_instruct_llm(model_dir)` → Midm-2.0-Mini-Instruct 로컬. |

### 3.4 기타 core 루트 파일

| 파일 | 역할 |
|------|------|
| `korean_embeddings.py` | **한국어 임베딩 초기화**. `USE_OPENAI_EMBEDDINGS`면 OpenAI, 아니면 HuggingFace (기본 `BAAI/bge-small-ko-v1.5`). `init_korean_embeddings()` → `Embeddings` 인스턴스. |
| `korean_llm.py` | **한국어 LLM 초기화 (레거시/대안 경로)**. `USE_OLLAMA` / `USE_HUGGINGFACE`에 따라 Ollama 또는 HF 파이프라인. `init_korean_llm()` → `BaseLanguageModel`. LLM 팩토리(`llm/factory.py`)와 별도로, 환경 변수만으로 빠르게 쓸 때 사용. |
| `langsmith_config.py` | **LangSmith 추적**. `LANGSMITH_API_KEY`, `LANGCHAIN_TRACING_V2`, `LANGCHAIN_PROJECT` 기반. `get_langsmith_config()`, `is_langsmith_enabled()`. |
| `rag_chain.py` | **RAG 체인 생성**. `create_rag_chain(vectorstore, llm=None)`. LLM을 주입하면 해당 LLM 사용, 없으면 `settings.openai_api_key` 있으면 OpenAI, 없으면 검색만 하는 더미 체인. retriever + 프롬프트 + LLM + StrOutputParser. |
| `vectorstore.py` | **PGVector + 임베딩**. `get_embeddings()`: OpenAI 키 있으면 OpenAI, 없으면 더미 `SimpleEmbeddings`. `get_connection_string()`: `settings.database_url`. `get_vectorstore()`: PGVector 인스턴스. `add_sample_documents`, `initialize_vectorstore`로 샘플 문서 추가/초기화. Neon 등 외부 Postgres 사용 전제. |

## 4. 의존 관계 요약

- **config**: 아무것도 import하지 않음 (순환 방지).
- **database**: config만 사용. domain/API에 의존하지 않음.
- **llm**: config, base 타입, providers. RAG/도메인에서 llm을 주입받을 때 사용.
- **korean_embeddings / korean_llm**: 주로 환경 변수. (필요 시 config 사용 가능.)
- **langsmith_config**: 환경 변수만.
- **rag_chain**: config, vectorstore(및 그 안에서 쓰는 embeddings), 선택적으로 llm.
- **vectorstore**: config, PGVector, embeddings(OpenAI 또는 더미).

즉, **core 내부**에서는 `config` → `database` / `llm` / `vectorstore` / `rag_chain` 방향으로만 의존하고, **core는 app의 다른 레이어(api, domain)를 import하지 않습니다.**

## 5. 개인 프로젝트에 적용할 때 체크리스트

- [ ] `config.py`: 프로젝트에 맞게 DB, Redis, JWT, LangSmith, **LLM 관련**(`llm_provider`, `openai_api_key`, `local_model_dir` 등) 필드 정의.
- [ ] `database/`: Base·mixin·session 구조 유지. 도메인 모델은 `Base` + 필요한 믹스인만 상속.
- [ ] `llm/`: 사용할 provider만 두고, `factory.py` 분기와 `Settings` 필드를 맞춤. 새 provider는 `providers/`에 모듈 추가 후 factory에서 선택.
- [ ] `vectorstore.py`: 연결 문자열·컬렉션명·샘플 문서를 프로젝트 도메인에 맞게 변경.
- [ ] `rag_chain.py`: 프롬프트 문구만 도메인에 맞게 수정해도 됨. LLM 주입 방식은 그대로 두면 됨.
- [ ] `korean_embeddings.py` / `korean_llm.py`: 한국어가 필요하면 유지, 아니면 제거하거나 다른 언어용으로 대체.

이 문서를 다른 Cursor AI(또는 팀원)에게 보여 주면, **app/core** 구조와 역할을 기준으로 MCP 스타 토폴로지의 핵심 레이어를 동일하게 맞추는 데 참고할 수 있습니다.
