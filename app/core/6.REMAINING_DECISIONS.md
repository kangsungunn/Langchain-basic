# 남은 결정 사항 정리

> core/orchestration → domain hub로 이동하기로 결정했으니,
> 이제 **남은 것들**을 정해야 합니다.

---

## 1. core/orchestration 정리 방향

### 결정: domain hub에서 정책/규칙 판단

**이제 정해야 할 것:**

| 항목 | 옵션 | 추천 |
|------|------|------|
| **core/orchestration 전체** | A) 완전 제거 | ✅ **A 추천.** domain hub로 이동했으니 core/orchestration은 더 이상 필요 없음. |
| | B) DecisionMaker만 domain으로 옮기고 나머지(WorkflowManager, LangGraph 등)는 스텁으로 둠 | ❌ 불필요한 복잡성. |
| **DecisionMaker** | → **domain/v1/minso/hub/decision_maker.py** (또는 shared)로 이동 | ✅ 이동. |
| **KoELECTRALoader** | → **core/ml에 유지** (인프라) | ✅ 유지. DecisionMaker는 domain에서 core/ml/koelectra_loader를 import. |

**결정 필요:**
- **A (완전 제거)** vs **B (일부만 스텁)**
  → **A 추천.** domain hub로 이동했으니 core/orchestration 폴더 전체 제거.

## 4. database.py 호환성 레이어

| 항목 | 현재 상태 | 옵션 | 추천 |
|------|-----------|------|------|
| **core/database.py** (파일) | 강사 구조에는 있음. 현재는 없음 (이전 정리 시 제거됨). | A) 다시 만들기 (호환성 레이어) | ✅ **A 추천.** `from app.core.database import Base, get_session, TimestampMixin` 같은 import가 동작하도록. |
| | | B) 안 만들기 (패키지만 사용) | ❌ 기존 코드에서 `from app.core.database import ...` 쓰면 깨질 수 있음. |

**결정 필요:**
- **A (다시 만들기)** vs **B (안 만들기)**
  → **A 추천.** 호환성을 위해 `database/__init__.py`를 re-export하는 파일 하나 만들기.

## 6. 다음 단계 (결정 후)

1. **core/orchestration 제거** (또는 DecisionMaker만 domain으로 이동 후 제거)
2. **core/mcp 제거** (또는 스텁)
3. **강사 구조 파일들** → 스텁으로 두기 (또는 지금 구현)
4. **database.py** → 호환성 레이어로 만들기
5. **domain hub에 DecisionMaker + MinsoHub** 구현

이 문서는 "남은 결정 사항"을 정리한 것입니다. 각 항목에 대해 **A/B/C 중 선택**해 주시면, 그에 맞춰 다음 단계(코드 수정·제거·이동)를 진행하겠습니다.
